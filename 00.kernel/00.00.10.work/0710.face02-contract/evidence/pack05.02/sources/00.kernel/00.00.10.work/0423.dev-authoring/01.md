## 1. The cycle
Discuss/record in N4NN -> resolve scope and decisions -> start authoring session -> add #NN items -> inspect notes/dependencies/coverage -> review exact draft -> freeze prepared pack on linked N5NN/05.NN -> Director releases -> builder/return/Prime review -> findings return to N4NN or next bounded pass.

Development can loop before coding. Work-item editing is not release, and discussion is not a command. This slice builds start through freeze; existing execution/return/review workflow continues. The first proof is Prime authoring a pack through these operations without writing a giant metadata document or one-off snapshot script.

## 2. Source and destination
A registered book profile names book instance/root, N4NN source files, linked N5NN work page(s), applicable template/version, declared note sources, dependency-set reference and allowed draft roots. Source-to-build relation is explicit: do not presume replacing the 4 digit with 5 yields a free or correct page. One source may eventually support several bounded build slices; ambiguity is shown for selection, not guessed.

For this first slice the concrete relation is 0423.dev-authoring -> 0526.dev-authoring. Existing 0526/05.01 is preserved. Compute chooses/reserves the next free pass atomically from this linked work page, not a new return-band page. It reports the exact slot immediately and refuses collisions. N5NN return intent is matching 0126.dev-authoring; N7NN remains page-local. A conflicting current occupant is visible pending/blocked custody, never invented receipt or sequential fallback.

## 3. Model-facing operations (names proposed, behavior required)
start(source): compute loads the profile, source/notes/template/dependency context, reserves the next pass and returns the small field form plus unresolved entries. Model supplies the bounded goal/scope/finish and executor/reviewer if not already explicit in the source; compute asks only for missing/ambiguous fields.
note(text, attribution, source): append a preserved draft note. Mark it discussion/proposal/recorded-decision only when supplied explicitly, with its source; compute cannot turn its own inference into Director authority.
add-item(content): compute assigns the next #NN, validates the small semantic form, attaches source-note links, records dependency references and renders preview. Repeated item input with the same request identity is idempotent; conflicting bytes are refused/preserved. No shell commands, numbers, paths or hashes are executed from prose.
revise(item/content): preserve the earlier item revision, keep stable identity and invalidate review/freeze evidence for changed draft bytes. Deletion/reordering is explicit; do not silently renumber references or discard content.
inspect: return whole readable draft and concise gaps/coverage/dependency status; expand exact linked sources on request. Unknown is not resolved. No repository-wide crawl for each item.
review: Prime supplies judgment on this exact preview, checking scope, source decisions, meaning, tests, dependencies and handoff. Compute records exact draft/template/source hashes, missing-field checks and attributed review; it does not judge that meaning is correct.
freeze(expected_digest): recheck source/notes/template/dependency bytes and review digest; snapshot declared inputs, emit final prepared N5NN/05.NN and manifest, preserve authoring record. Refuse stale/missing required inputs or a changed review target; never overwrite an occupied pass. No build, send, approval, seating, Git publication or return allocation is implied.

## 4. Template: what the model supplies versus compute owns
Compute header: book/source/work/pass/template/version/date/attribution/links; stamp draft/prepared accurately, never approved by default.
Intent: goal; in-scope; exclusions; finish criteria; executor/reviewer; allowed changes. Meaning comes from the model/Director sources, and undeclared values remain missing.
Notes: preserved entries with source/attribution, disposition and destination. A declared note is integrated into #NN, deferred with reason, rejected with reason or unresolved. This is coverage of declared notes, not proof every sentence in source prose was understood.
Items: #NN title; purpose/change; requirements; allowed changes; interfaces/dependencies; observable acceptance/evidence; source-note refs; open choices. Compute supplies numbering, field layout and mechanically derived refs/hashes. Template indicates which fields are required, optional or explicitly not applicable; no blanket boilerplate to satisfy missing meaning.
Dependencies: explicit module/resource/environment references, required/optional/conditional status, resolved identities/pins, source declaration, missing/stale/ambiguous/cycle state and help route. Compute consults the pinned dependency reader/set; model supplies unknown relationships and judgment, not hand-calculated hashes. Declared closure is not proof of all runtime dependencies.
Review/footer: exact review binding, mechanical checks, outstanding issues, output and return intent, preservation/stop conditions. Compute owns formatting; model supplies decisions and content.

## 5. Single draft authority and preservation
Each authoring pass has one canonical authoring record, stored with that work pass under evidence/authoring05.NN. It owns authored draft content and revision history. draft.md and gap reports are derived. Source N4NN decisions remain authoritative for their own meaning and are pinned references, not rewritten into a competing authority. Manual editing of derived Markdown is a conflict, not silently imported.

The emitted 05.NN is a frozen prepared instruction artifact with exact source/template/authoring/review provenance. Later edits require the supported revision/new-prepared-version route and a new review; release remains separate. New/copy writes are staged/exclusive and retain prior state/partial evidence on interruption. Errors identify failed field, expected shape, retained input and correction/help route. UTF-8 is explicit for every read/write; return/source blobs are byte-preserved.

## 6. Reuse and present limitations
Use existing pack path/custody validation and dependency-reader semantics where sufficient. Reuse the old assembler for its supported Git-blob case only if it actually reduces work. A worktree adapter must label measured-file input and snapshot exact bytes without pretending they were committed. No parallel dependency resolver or shadow work ledger. No new universal grammar, face system, worker scheduler or migration engine.

Current matching 0126 is occupied by legacy material. The author can produce/review an unreleased draft while custody is pending. It must not claim a ready return route or fall back to 0184. Finalization reports exact unresolved conditions; any temporary custody exception needs a recorded existing policy, not a model-improvised escape. The 01NN repair owns freeing that destination.

## 8. First-slice acceptance
Incremental real subprocess commands, source reload, two work items, pause/resume in a new process, explicit source-note dispositions, dependency resolution/missing state, exact full-document review and freeze. Demonstrate model input never names a pass path/number/hash. Source/template/dependency/item edits invalidate readiness. Two simultaneous start attempts cannot reserve the same pass. An interrupted draft update retains previous state. The next current-Prime pilot uses the tool to author one real next pack; a golden-template test alone is insufficient.
