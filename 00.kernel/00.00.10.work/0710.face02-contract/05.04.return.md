## Hostile
- **I wrote the simulator, the template and all 35 expectations.** Prime's two probes are the only independent cases, and they are reproduced exactly. **A fresh reviewer should add their own probes,** for example editing the plan record itself, or swapping two pages' warehouse files.
- **A known gap that holds safely but has no case yet:** the plan record could be altered after J1, and no case covers it. `journal_ok` checks only its keys, not that its hashes still match the stored images. The images are content-addressed, so a forged plan pointing at other images would be caught only if those images are missing. **This needs a signed or hashed plan in the real tool** (overflow).
- **The face I was tempted to obey as live:** my own 05.03 "restart checks hashes, never labels" line in the update draft. It was a claim the code did not meet. This pass makes the claim and the code match.
