## Purpose and state
Record how workshop work can be decomposed among Director, Prime, compute and model
assistants. Director intent is in06.01. This is an N4NN design page, not seated law,
an executable job, a new standing role assignment or permission for API expenditure.
No runtime, model call, queue worker, timer or automated retry is built by this page.

## Intended division
Director sets goals, resources, consequential preferences and authority. Prime designs
the work, chooses boundaries, supplies judgment and reviews consequential results.
Compute executes declared steps, retrieves exact records, constructs prompts, invokes
an explicitly configured model when authorized, checks supported conditions, retains
attempts and hands back evidence. An assistant supplies bounded interpretation or
candidate content. It may run before Prime is handed the result; it is not another
Prime with power to widen the task. 'Cheap compute' here means model inference,
which is distinct from deterministic code.

## Candidate decomposition
| Task | Compute | Model assistant | Prime/Director |
|---|---|---|---|
| Find relevant prior work | Exact search, address/filter/source retrieval | Suggest terms, rank passages, explain relevance | Resolve ambiguity that changes design |
| Prepare a report | Gather immutable sources, test/custody facts | Draft supplied-scope summary with citations | Assess meaning, omissions and next action |
| Compare revisions | Exact diff and section inventory | Identify likely meaning changes | Decide consequential preservation/conflicts |
| Process findings | Validate shape, preserve IDs/source bindings | Propose grouping/duplicates/questions | Accept disposition or request Director judgment |
| Execute exact mechanical work | Formatting, hashing, counting, timers | Normally unnecessary | Define task and exceptions |
These are proposals, not implemented routes. Cheapness alone is not grounds to move
semantic authority or replace an exact calculation with a model answer.

## Recorded route, not improvised authority
Prime hands compute a bounded ticket: goal, input/source identities, allowed steps,
outputs, model/effort configuration, checks, resource/retry limits and handback route.
Compute can execute the recorded chain without another Prime prompt for each step.
The assistant's output is data. It cannot alter its own grant, configure another
provider, launch commands, add tools or turn a proposed task into authorization.
Where tools are allowed later, their explicit operation/schema bounds belong in the
ticket. Exact code enforcement applies only to supported callers, not every model.

## Validation and retry
A mechanical failure may justify an automatic repair attempt when the ticket permits:
wrong schema, invalid address, unresolved citation, missing required field or failed
specified check. Retain the original output and machine-readable diagnostic; the
next attempt receives the concrete defect and relevant inputs. Do not erase failures
or silently allocate new identities. Identical replay can reuse verified work.
A valid shape does not prove a summary faithful, a ranking useful or a conclusion
correct. Semantic assessment requires an explicitly designed test/evaluator or Prime
review. A second model's agreement is evidence, not proof or approval. If correctness
cannot be determined, say unverified rather than treating another retry as success.

Retries are bounded by caller-supplied attempt, token/cost and wall-time ceilings.
No default unlimited loop or invented numeric budget. Stop at a limit, repeated
unchanged failure, missing capability or task dependency on unresolved judgment.
Preserve partial work and return what failed, what changed, checks and limits.
Two reviewed unresolved passes follow the existing elevation rule; two tool attempts
are not automatically two reviewed passes. Design conflict/fork or required Director
judgment stops affected work under0412. Independent authorized work may continue.

## Record and handback
Keep original inputs/outputs, provider/model/effort/settings, timestamps, usage when
exposed, prompt/recipe version, checks/evaluator identities, diagnostics and result
hashes. Unknown cost/usage stays unknown. Summaries point to original evidence and
preserve disagreement/uncertainty; never replace Director's exact words.
Distinguish assistant-produced, mechanically checked, semantically reviewed and
accepted output. Handoff to Prime includes useful result, supporting sources,
verification, attempts/resources and unresolved questions. Routine progress remains
visible; a successful substep does not become page completion or wider authority.
Page-local reasons and decisions land on affected work pages. An index only points.

## Adoption and first experiment
Build only after a bounded implementation pack declares the route and limits. Start
with one small interpretive task Prime actually repeats, not a general autonomous
assistant framework. Proposed first candidate: rank a fixed retrieved set and draft
a source-cited evidence brief; Prime still reads decisive evidence. Include difficult
negative cases, omissions and conflicting records. Benchmark human/Prime corrections,
false omissions, useful retrieval, accepted results, total model/retry/reviewer costs,
latency and Director attention against the same task done without assistant support.
Use fresh matched cases and record effort/configuration; no claimed productivity
multiple from this proposal. Haiku/Luna are candidate examples, no model chosen.
Benchmark coordinator and evaluated workers remain distinct; design/implementation
questions belong in future explicit work, not tasks generated by this page.

## Open design choices
Choose first task/model and supported execution surface; define semantic acceptance
and evaluator independence; set explicit initial budget/limits; decide trusted caller
and idempotency boundaries; determine local versus hosted provider access. Ask the
Director only where preference/resources/design require it. No missing choice is
permission to incur cost. Existing builders continue in their assigned scopes.
