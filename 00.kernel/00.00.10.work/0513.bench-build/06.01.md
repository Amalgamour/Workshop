## Choices (before code)
C01. **One module, plain records.** `labs/prime-bench-pass01/prime_bench.py`, standard library, with the commands `validate`, `prepare`, `collect`, `event`, `assess`, `review`, `compare`, `export`. JSON records; every write an exclusive create. No orchestration engine, no scheduler, no model or session API.
C02. **Bench version.** `bench.json` lists every case file (candidate, evaluator, coordinator), the conditions file and the support pins, each with sha256 and bytes. The bench version is the sha256 of the bench.json bytes. `validate` re-hashes everything and refuses drift.
C03. **Three separated trees per case.** `candidate/` (task and synthetic sources, the only thing a tested session sees), `evaluator/key.json` and `evaluator/rubric.json` (fixed before any answer), `coordinator/meta.json` (family, matched variant, decisive evidence, ambiguity notes). Case ids and family names never reach the candidate; the candidate sees only an opaque run id.
C04. **Two destinations per run.** `prepare` writes a fresh coordinator run directory and a separate fresh candidate directory, neither inside the other nor inside the repository. The candidate gets the task, sources and, for assisted only, a copied and re-pinned prime_review.py with its README and CONTRACT. Each evaluator key carries a canary; `prepare` refuses if any canary or evaluator/coordinator file appears in the candidate kit.
C05. **Declared capabilities.** fresh-session, workspace-confined, tool-log and usage are each `supported`, `unsupported` or `unknown`, supplied by the coordinator. Anything but `supported` for isolation is reported as not clean; it is never simulated.
C06. **Collection.** Exact raw response bytes, optional raw tool log, optional normalized tool-event JSONL, optional usage JSON, coordinator-recorded start and finish, session label, isolation actually used, status completed/failed/abandoned with reason, and any intervention. Missing data is `unavailable`, never 0. The response's first line must name the run; a different run id refuses as wrong identity. A second collect refuses: identical is `already-collected`, different is `conflict`. Corrections and interventions after collection go to separate append-only event files; the original is never changed.
C07. **Assessment.** Deterministic code checks only: run line, outcome label, decisive evidence mentioned, exact quotes preserved, forbidden claims absent, canary absent. It refuses if the key or rubric bytes differ from those pinned at prepare. Semantic rubric scores come only from a supplied reviewer record bound to the run, case revision and rubric sha256; a changed rubric refuses.
C08. **Comparison.** Refuses mixed bench versions, mixed investigations, duplicate run ids or directories. A clean run is completed, fresh and confined as declared, unique session label, no intervention, no leakage, keys unchanged. Unclean, failed and abandoned runs are listed with reasons, never dropped. Output is per-run rows and counts; no score multiple, no time or token saving.
C09. **Colab adapter.** `export` writes a new folder outside the repository: the comparison (markdown and JSON), copies of every run record, a `05.NN.return.TEMPLATE.md` with Did/Blocked/Need left for the coordinator, and the exact `return_capture.py capture` command for a Prime-reserved member. Runs must bind the same investigation record, which keeps exact Director replies with source references.
C10. **Cases.** Synthetic, labelled SYNTHETIC, small, with real rule provenance (0512 prime-review CONTRACT, 0414 method). Families: correction (claimed count vs log; boundary bug), false completion (hidden verify exit 1; missing artifact), design fork (two valid replay semantics; mutable vs frozen notes), complete (clean return with a documented accepted limit; clean return with a cosmetic quirk recorded as accepted). The baseline can solve every case by reading; nothing is withheld from it but the support module.
C11. **Tests.** All four families with labelled SYNTHETIC responses, missing usage, contaminated/shared-context run, changed rubric, wrong identity, duplicate/conflict, failed/abandoned run, evaluator leakage, unsafe paths and partial writes. No fixture test demonstrates model performance.

## Risks to watch
R01. Inventing an engine. Mitigation: manual RUN-GUIDE; the code only prepares, records, checks and tabulates.
R02. Straw baseline. Mitigation: the decisive evidence for every case is in plain candidate files; the support module only shapes the report.
R03. Hidden leakage through the repository. A tested session that can read lib-build can read the keys. Mitigation: candidate dir outside the repo and `workspace-confined` declared; unknown or unsupported is reported unclean.
R04. Parser overreach. Mitigation: deterministic checks are labelled as such; semantic quality is only a reviewer record.
