## Choices (before code)
C01. **Trial seal replaces single-run prepare.**
- `seal --plan --investigation --dest` prepares every planned run of a trial in one step, into one fresh trial folder. It writes `seal.json` last.
- The plan (`prime-bench-plan/1`) binds the trial id, every run (id, pair, case, condition, order, labels), declared capabilities, allowed differences, the preparation owner and setup, and the amortization statement.
- The seal binds:
  - the plan and investigation bytes;
  - the bench version and rules;
  - harness, conditions and measures hashes, plus the support pins;
  - each case's key, rubric and commitments hashes;
  - each run's run.json and delivery manifest;
  - pair parity results;
  - the machine clock at seal start and finish.
- A standalone `prepare` is removed. One run alone cannot be a clean comparison.
C02. **Parity within a pair.** Seal re-reads both delivered kits and requires byte equality for every file except the declared allowed differences: `support/*` in assisted, and the PROMPT.md Tools paragraph and run id. PROMPT.md is checked by regenerating it from the fixed template. A missing or changed decisive file refuses the whole seal (C01 specimen). Variants a and b are never compared byte for byte.
C03. **Baseline reach.** Every decisive file, meaning TASK.md and `sources/*`, must be present in the baseline kit. Parity enforces this; the seal also records it explicitly.
C04. **Protected inputs versus working outputs.**
- The delivery manifest lists every delivered file. The candidate may write only under `work/`, which is created empty.
- `check-inputs` (read-only, run before launch), `collect` and `compare` each recheck the kit, reporting `changed`, `missing`, `extra` and `linked` (symlink, junction or hard link). Files under `work/` are ignored, but `work/` itself must not be a link.
- Collect never refuses on drift. It keeps the raw response and records the failed check, and the run can never be clean (Prime's probe).
C05. **Corrections are new identities.** `rerun --trial --supersedes rX --run-id rY --reason` prepares a fresh kit for the same case, condition and labels. It records an append-only amendment. The original run and its evidence stay. A late run is reported but is never clean, because it was not in the pre-answer seal; a clean replacement needs a new sealed trial.
C06. **Whole roster.** `compare` and `export` take the trial folder, not a list of runs, so a favourable subset cannot be picked.
- Every planned run appears; one not collected is `uncollected`.
- A pair is readable only when both its runs are clean.
- The report states how many planned runs were collected and how many pairs are readable.
- A run whose run.json differs from the seal is listed as invalid, not dropped.
- A declared start before the seal's machine time is not clean.
C07. **Action commitments.**
- `evaluator/commitments.json` (`prime-bench-commitments/1`) holds per-case commitments of kind `required-action`, `hold`, `prohibited` or `no-further-edit`.
- `actions --run-dir --record` takes a supplied `prime-bench-action-assessment/1`: one disposition per commitment, `present`, `contradicted` or `absent`. Present and contradicted need evidence that is an exact substring of the collected response; absent takes none.
- Code validates the record and its bindings (run, case revision, commitments sha256, evidence in the response). It infers no meaning.
- Report tallies are per kind. There is no universal score.
- String checks keep their label, "deterministic string checks". Quote preservation stays a separate string check and rubric item.
C08. **Costs.** `measures.json` (`prime-bench-measures/1`) defines:
- the operation unit;
- the named session start and stop events;
- the preparation timing (seal start to finish, by machine clock);
- every cost field with its unit.

A supplied per-run `prime-bench-costs/1`, given at collect, covers launch order, tool operations, failed tool calls, request repairs and their minutes, correction loops and their minutes, Director attention events and minutes, cache state and prior involvement. Null means unknown.
- The report marks each run's cost record complete or incomplete, naming the missing fields.
- Trial-level preparation (owner, reusable versus per-run setup, amortization) comes from the plan.
- Every value is tagged `mechanical` (harness hashes, checks, seal clock) or `declared` (human-supplied).
C09. **Versions.**
- Rules become `prime-bench-rules/2`, with bench revision 2 and case revision 2 for the new commitments file.
- Run becomes `prime-bench-run/2` and collection `prime-bench-collection/2`.
- A `prime-bench-run/1` folder is refused as `legacy-run` by collect, compare and every v2 command. It is never treated as satisfying the new controls.
C10. **Chronology and isolation limits stay declared.** Hashes show byte equality at check time. They do not prove when a session started, that it saw nothing else, or that the seal was published before launch. The guide tells the coordinator to send the seal digest to Prime before the first launch, so that someone other than the coordinator holds a record of it.
