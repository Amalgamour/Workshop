## Run procedure

1. Read this contract, your 05.NN.pack, RUBRIC.md and README. State actual model/build
   if exposed, session familiarity and original Builder participation. Do not call
   an existing Builder context fresh or an instruction-separated folder blind.
2. Verify the seal, then prepare your four run folders once. No source Git changes:
   setup creates isolated disposable Git repositories inside your assigned runs.
   Setup has a separate timer. Copy time is not a per-turn Prime saving.
3. In the declared sequence, review the run's common case.json, assignment projection,
   captured return, notes, contract, artifact files and relevant supplied context.
   Verify source/custody/artifact claims. Separate what you read, calculated or
   actually tested from reported results. Missing dependencies remain unknown.
4. Manual: ordinary file reads, searches, Python and Git are allowed. Do not invoke
   the reviewed optional Prime assistance bundle or use its reports as judgment.
   Historical target code may be inspected and tested as subject evidence in BOTH
   conditions. Testing the packet helper itself is not using it to review the case.
5. Assisted: use the frozen assistance/ interfaces. At minimum perform journalled
   read with templates, packet gathering, supply your own judgment, record, re-read
   and day inspection with the generated registration. Journal root is run/out/journal,
   outside the disposable repository. The tool supplies bindings, not conclusions.
   Inspect its packet coverage: the adapter's default packet is NOT a complete
   artifact inventory. Directly check common source files where necessary. Both
   conditions may run identical bounded target checks. Extra helper setup/refusals
   count as assisted effort. Do not repair or change the assistance to make it win.
6. Use replay_lab.py command for subprocesses so actual command outputs/exits/times
   survive. Direct file-reader/tool calls are not covered; maintain access.jsonl
   with file/operation/purpose and mark those entries self-reported. Record manual
   address/binding copies and corrections in friction.md. Do not invent exact
   counts retrospectively when unavailable. Preserve interruptions and failures.
7. Save deliverables/review.md and deliverables/next-pack.md for EACH run. Review:
   Did/Blocked/Need, verified versus claimed, defects and meaningful unknowns,
   disposition, pass-finished versus goal-complete, Director needs, preservation,
   one bounded next action, Factfind/Hostile/Overflow/Unprompted. Next-pack: clearly
   LAB ONLY — NOT RELEASED, with problem, scope, exact sources, steps, exclusions,
   verification and return expectations. If no further build is justified, write
   a reasoned NO PACK REQUIRED. Do not invent work to satisfy the file requirement.
8. Save run-summary.json: status complete/partial/abandoned, started/ended UTC where
   observed, familiarity/carryover, checks, decisions, manual-copy counts or null,
   source exposure, interventions and tokens/cost with units or null. Explain limits.
   The judgment is yours; no wrapper produces it. No generated fake review batches.
9. Only AFTER all four deliverables are preserved, write runs/<model>/return.md with
   the within-model comparison. Do not read coordinator/history yet: Prime will
   compare all sealed returns with history after every model has submitted. Explain
   what helped, what slowed you, what still required intelligence, useful failure
   messages and the smallest supported next improvement. No unsupported uplift ratio.
10. Export your own model once; retain any partial export. Check exported files,
    measurements and index. Publish the N7 return and capture only as your pack
    directs. Do not change another model's output. Do not stage, commit or push.

## Finish and review

One model's return is complete only with all four run outputs OR explicit partial
status, actual retained command logs and source checks, exported file index and
measurements, and the captured return. A finished pass is not the overall Prime
milestone. Prime retains every result, then evaluates within-model differences,
cross-model patterns and historical follow-through. No actual build is released
from an experiment's next-pack proposal. Director judges any consequential change.
