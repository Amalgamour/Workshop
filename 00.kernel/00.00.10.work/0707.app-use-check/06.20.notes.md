## Current versus proposed versus guaranteed
- **Current:**
  - no pair rule (05.19 X2 bound `06.15.notes.md` as the "return");
  - orphan or missing pack is incomplete via `assignment-missing`, but there is no explicit orphan state;
  - chronology is not observed at all;
  - N1 is reported as missing.
- **Proposed (prototype `labs/n7-local-lifecycle-pass01`):** an N7-only overlay on the accepted pass04 chain that adds an `exchange` object to the intake and enforces:
  1. **local pair:** the assignment is `{pass}.pack.md`, and the declared submission equals `{page}/{pass}.return.md` exactly; otherwise the intake is incomplete with a named state;
  2. **explicit states:** `matched`, `orphan-return`, `pack-missing`, `pointer-pending` (unfiled return), `return-not-local`, `assignment-not-pack` (legacy name);
  3. **N1:** `not-applicable` in the exchange; the finding `custody-missing` is replaced by `n1-not-applicable` for N7 only;
  4. **chronology:** a lab `open` command records the pack body before any return exists. The intake reports `recorded-before-return` or `unverified` (never inferred from mtime);
  5. **freshness:** the N7 pack is bound by its region before `## Review`, so a later Review-section edit does not stale the exchange. A task-body or pointer change still does.
- **Not changed (label, documented):** the record `custody` field and its rendered line stay `missing`. Changing them is a shared-schema change at `pass02.do_record` / `pass01.render_body`, proposed for production; prototyping it would mean rewriting do_record at runtime, which I will not do.
- **Guarantees claimed:** only what the cases show. No concurrency, power-loss or AR-01 claims.
