## Minimal adapter delta (0420/06.57)
- **New schema `harness-inputs/3`.** It is harness-inputs/2, plus the candidate block, which now has to declare:
  - `entry`: the actual on-disk entry, `app/librarian.py`;
  - `workbook_entry`, and optional `open_entry` / `reporter_entry`: each must be one of the declared files;
  - `files[]`: path, sha256, bytes, `role` (entry, workbook, open, reporter, dependency, adapter, declaration, data);
  - `lab_differences[]`.
- **Metadata paths are untrusted:**
  - relative, POSIX, with no `..`, no drive letter, no backslash, no leading `/`;
  - unique;
  - a regular non-link file inside the root;
  - hash and length must match;
  - only a supported schema is accepted.
- **Execution-target proof (controlled tamper, disposable only):** in a NEW copy of the candidate, append `raise SystemExit("LAB-TAMPER-<nonce>")` to the declared workbook (and the open or reporter entry, when declared), then run a fixed probe through the declared entry.
  - **Identical (exit, stdout) to the untampered control** → the declared target is NOT executed → **DECOY → refuse.**
  - Other declared dependency files can be traced the same way. **They are flagged, not refused,** because a baseline legitimately carries unused files.
- **Legacy (explicitly labelled):** harness-inputs/2 is accepted ONLY for the two frozen baselines, by CANDIDATE.json hash: proto-l 172ec4e9…, staged-g 062a3c8d….
  - The old discovery then runs labelled `legacy-discovery`, and the derived workbook still goes through the same tamper proof.
  - **Any other harness-inputs/2 (e.g. Prime's old combined identity) refuses** with its real reasons.
  - Old manifests are not migrated or repinned.
