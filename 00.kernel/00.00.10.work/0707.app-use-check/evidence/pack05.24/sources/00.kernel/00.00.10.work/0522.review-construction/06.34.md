## Identity rule

The successor applies only when the live kind is N5NN and a stored intake object exists. It uses the stored `book` and `instance_id` fields and the live book already resolved by `book_dir`. It adds no registry and no rebind.

A stored book string is resolved with the same acceptance rules as `book_dir`: absolute, no `..`, no UNC, a real unlinked directory, ancestors unlinked, then `Path.resolve()`. Spelling that resolves to that same directory string is the same root. Two different resolved directory strings stay different roots.

Current applicability stays with the predecessor when all of these hold:

- the stored book resolves to the live book string
- the live intake's `book` equals that live book string
- the stored `instance_id` equals sha256(canonical `{"book": live book string, "pass": live pass, "source": live page}`)

Otherwise current applicability is held. `source_changed` returns true before row equality can clear it. The hold reasons are:

- `different-root`: the stored book resolves to a different existing directory, and the stored instance id is not the live instance id
- `identifier-disagreement`: one of book or instance_id matches the live root and the other does not, or the live intake book field disagrees with the resolved command book
- `relocation-or-clone`: the stored book is a plausible absolute path and does not resolve to an existing directory, so a move and a clone are not distinguishable from the stored fields
- `unbound`: `book` or `instance_id` is missing or malformed, or the stored book is not a plausible absolute path

An unbound or relocated record stays historical. The successor does not infer identity from file names, dates, or equal row hashes. A later rebind or relocation workflow is a separate pack.

Same-instance commands, including a later byte change of a declared file, keep the predecessor `source_changed` result. N7NN and unrouted kinds keep the predecessor `source_changed` result. N7 strict parsing stays the pass05 parser. This layer does not add `n1-not-applicable` and does not remove `custody-missing`.
