## API and error delta (pass05 → pass06)
- **Path-text rule (shape stage, no filesystem access):**
  - It covers `--config`, `--evidence`, `candidate.path`, `dependencies[].path`, `interpreter.path` and `output_root`.
  - It requires a non-empty string of at most 32767 characters with no NUL or other C0 control character.
  - A failure is `config-path` (for config fields and the CLI config path) or the guard's `path` code (for evidence).
  - **The unknown candidate's path is checked as a string only and never opened.**
- **Narrow translation, `ValueError`/`OSError` only, at these named sites:**
  - the guards' `lstat`, `abspath`, `lexists`, `realpath`, `isdir`, `isjunction` and `mkdir` → `path-os`;
  - `read_config` → `config-read`;
  - `check_file_pin` → `pin`;
  - the interpreter probe → `interpreter` (it also catches the probe's timeout);
  - `fresh_dir` → `occupied` (on FileExistsError) or `path-os`.
- **Entry behaviour:**
  - **An invalid evidence path gives REFUSED with no run directory and no fallback location** (the CLI prints the reason).
  - **A config is read only after the evidence destination is accepted.** Its raw bytes are kept only in that run directory.
  - **When the run, case or fixture directory cannot be created:** a run directory failure gives REFUSED with nothing written; a fixture root failure gives REFUSED recorded in the run; a case directory failure makes that case ERROR.
- **Not swallowed:** every other exception propagates, and the planted-TypeError test shows it.
- **Small internal changes:**
  - `canonical()` finds the existing prefix with `lexists`, so a dangling link refuses (`path-os`) rather than being treated as absent;
  - the fixture guard marker is named `_pass06_guard`;
  - the run record adds `reused_pass05` hashes;
  - `code_sha256` names `harness6.py` and `guards6.py`.
