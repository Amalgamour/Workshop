## Cause (source)
- **Shape check:** `validate_config` checks only that the path-bearing fields are non-empty strings.
- **The raise:** `guards.chain_without_links`, `canonical` and `fresh_dir` call `os.lstat`, `realpath`, `exists` and `mkdir` with no handling for `ValueError` (NUL) or `OSError` (an invalid Windows name, a permission error).
- **The leak:** `main` catches only `Refused`, so the error escapes as a traceback.
- **Same class elsewhere:** the CLI `--config` path in `read_config` (`is_file`, `read_bytes`), `check_file_pin`, and the interpreter launch in `preflight`.

## Method (fixed before code)
1. **NEW pass06** with the smallest coherent change:
   - `guards6.py` is a copy of pass05 `guards.py`, with path-text validation and **narrow** `(ValueError, OSError)` translation around each filesystem call.
   - `harness6.py` is a copy of `harness5.py`, with shape-level path-text validation for every path-bearing config field and narrow translation at `read_config`, the evidence directory creation, `check_file_pin` and the interpreter probe.
   - **Reused unchanged by hash:** pass05 `winjob.py`, `stub_cases5.py` and `stubs/STUB5.py`; pass04 `cases.py` and `fixtures.py` (as before). Each is listed with its pin in the run record.
   - **No other behaviour changes.** pass05 is untouched.
2. **Rule for "expected" errors:** only `ValueError` and `OSError` raised by a filesystem or path call, or by the interpreter launch, at those named sites. Everything else (TypeError, KeyError, internal bugs) propagates. A test shows that a planted TypeError is not swallowed.
3. **Path text rule** (shape, no filesystem access): a string that is non-empty, at most 32767 characters, and free of NUL and other C0 control characters. **This applies to the candidate path too, but it is a string check only. An unknown candidate is never opened.**
4. **Evidence.** First, reproduce H04 through the **public pass05 CLI** (`harness5.py preflight`, which writes nothing). Then the same input through `harness6.py`, followed by real malformed-path negatives:
   - **H04 through `harness6.py`:** a NUL in the output root; an invalid Windows name; overlong text;
   - **CLI path and evidence:** an invalid config path through the CLI; an invalid evidence path through the CLI (no run directory anywhere); NUL variants through direct calls (Windows argv cannot carry NUL);
   - **known candidate and its dependencies:** a NUL in a known candidate's path; an invalid dependency path;
   - **interpreter:** a NUL in its path; an interpreter that is not an executable;
   - **one labelled MOCKED failure:** a permission error from `os.lstat`;
   - **not swallowed:** a TypeError from the guard propagates.
5. **Regression:** pass05's 20 self-tests are imported (their `main` is never run) and rebound to `harness6`/`guards6`, with new evidence and scratch locations. They run once. Then the real matrix with a null candidate runs once (UNREADY, no launch). All evidence goes to NEW `evidence/lab05.07`.
