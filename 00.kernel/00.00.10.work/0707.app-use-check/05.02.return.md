## 5. Portability (summary; full text `PORTABILITY.md`)
**Current.** Four files hard-code `D:\Git\lib-build`: the door (guard only), the loop, the cycle and the constructor.
- Module-relative already: `librarian.py`, the door's code_root, and the three readers.
- Windows-only checks degrade safely by construction (`getattr`, `hasattr`). This is source reading.

**Proposed.**
- All four derive their roots from module location, **together**.
- Each guard protects the *running* checkout.
- A missing pinned file becomes a refusal, exit 2.
- The loop, cycle, constructor and door are repinned, with records in the 0525 v2 representation.
- A "one line" fix to the loop would move the first failure to the cycle. That is source reading, which Prima's #04 also flagged as untested.

**Acceptance:** P1–P9 cover the native Windows regression, a relocated Windows copy, containment inside the copy, Linux describe and the full path, missing-file refusal, a symlinked root, and mismatched roots.

**Order:** usability first, then portability, by one owner, sequentially. The slices share the loop and constructor successors and the door pins. Do not write slice-1 files module-relative while the cycle stays on `D:`.

## Factfind (opinion lives here only)
- **The repairs line up with the existing division of labour.**
  - The constructor already owns "what may be written where"; F8 asks it to say so earlier.
  - The cycle already owns the decision; F4 asks the renderer to stop dropping part of it.
  - The loop already owns orchestration; F7 asks it to stop speaking in the reviewer's voice.
- **None of the four needs a new decision, gate or command for the operator,** apart from the read-only `inspect` inside the constructor, which the operator never calls directly.
- **The guide alone removes most of today's code reading.** It is worth publishing now even if the build waits.

## Hostile
- **I designed fixes for findings I raised myself.** Prime's review endorsed them, but I may over-weight them.

- **`constructed-same-binding` is not the same as idempotent:** a different judgment under the same binding still conflicts at render. The text says so, but an operator might read "same binding" as safe.

- **The disposition fixtures were only checked by the cycle's `check_judgment`,** not rendered. Rendering held and accepted is A4.1 and A4.3, for the builder.
