## Choices (before code)
C01. **Derive, then compare.** The checker rebuilds the identity, the exchange names, the envelope roles, the source to snapshot map, the support projection, the ZIP identity, the evaluator list and the full preimage from the package bytes and the fixed v2 rules. It recomputes both the assembler digest and the package digest itself. Any handoff field a consumer relies on that differs from the rebuild is a refusal. Output identity comes ONLY from the rebuild, and only when the result is `valid`.
C02. **Fixed rules restated in the checker, from the accepted contract and producer behaviour.**
- The names come from the pass.
- The colab file order is ENTRY, pack, notes, the return template, the review template, binding.json, colab-request.json, then support/SUPPORT.md.
- The support mapping is fixed.
- Roles are fixed.
- The request schema must be `colab-request/2`, the binding must be `colab-binding/1`, and binding.json must equal the canonical JSON of `request.binding`.
- Manifest paths must equal the unique target paths followed by the required sources.
- Each target's sha256 must equal its snapshot.
- The assembler request's origin, identity, revision and paths must match the binding and the manifest.
- A preimage part kind other than `text` or `file` refuses.
C03. **Bounded capability, stated in output.**
- The rendered prose (ENTRY, pack, notes, templates, SUPPORT, the assembler draft) is bound by digest, but not re-rendered.
- Heading-section line ranges are not recomputed.
- Pins and the assembler receipt's checker result are not re-run.

Each is listed in `not_verified`, with "use the pinned full producer verify for those". Informational handoff fields (`verify`, `statements`, `digest_rule`) are reported as unbound and never echoed as trusted.
C04. **Safe reading.**
- JSON is strict: no duplicate keys, no non-finite numbers, the right types, size limits, and no missing or unknown keys in the handoff.
- Every relative path is validated before use (no absolute, drive, UNC, backslash or traversal path).
- Each file and every ancestor up from OUT is checked for symlinks, junctions and reparse points, and files with a hard-link count above 1 refuse.
- The OUT package file set must equal the derived set; an unknown extra refuses.
- A duplicate ZIP entry refuses.
- A `*.return.md` or `*.review.md` anywhere in OUT refuses.
- Exit 0 means valid, 1 a bound-claim mismatch or tamper, 2 a refused or malformed input. There is never a traceback.
C05. **Copy.**
- It runs a full check first.
- The destination must be fresh: absent, under a real parent, not inside OUT, and with no linked ancestor.
- Files are written exclusively, then the destination is re-hashed and the source re-checked.
- An existing identical copy is `already-copied` (read-only, exit 0); a different or partial one refuses with the retained files listed.
- A failed write is `partial`: the files are kept, never deleted, never resumed.
C06. **Tests**
- HC01 itself.
- One tamper per claim field: investigation, binding, binding_sha256, exchange, not_created, envelope role, source_map, support_projection, zip, layout, digest_domain, the preimage (order, kind, extra part) and evaluator.
- Byte tampers.
- Malformed JSON.
- Unsafe paths and links.
- Unknown extras and duplicate ZIP entries.
- Copy replay, collision and partial.
- A valid package checks and copies exactly.
- For the relevant tampers, the full frozen producer verify is compared too.
- The frozen hashes are asserted before and after.
- The existing v2 suite is run as a regression. v1's unchanged suite is not run, per the pack.
