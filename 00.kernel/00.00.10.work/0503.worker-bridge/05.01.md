## #02 — Build one local-process adapter and a reproducible demonstration
Implement only one backend: a configured development worker process, invoked
without shell interpolation, exchanging a structured request/result via documented
stdin/stdout or explicit lab files. Allowlist the fixture executable/arguments for
this pass. No command pulled from untrusted result text gets executed.

Demonstrate: prepared request -> adapter invokes fixture worker -> worker reads
named fixture input -> writes one result artifact -> adapter correlates/verifies
response -> produces a durable receipt. Do not use the earlier lab's fixed-order
role launcher as a substitute for actually implementing the invocation boundary.

Separate protocol test workers from real model workers in every report. Support
finite timeout and bounded captured output; record failure without losing request
identity or overwriting earlier diagnostics. A timeout after launch can mean the
outcome is unknown, not that no work happened. Do not automatically relaunch an
ambiguous task. Duplicate identical results should not apply twice; reuse of an
identity with changed inputs/result should refuse or require a new identity.

The receipt is lab transport evidence, not a second authoritative production
ledger. File/path validation is not OS sandboxing: state the actual confinement
limits of a same-user subprocess. Require referenced artifacts to resolve inside
the allowed output root and match their declared bytes before reporting collected.
No kernel/runtime modules are seated or executed by this lab.
result: DONE. One backend only: LocalProcessAdapter (bridge/adapter.py).
- Launch: argv list with shell=False and an exact allowlist (profiles.json: 11 profiles, every one a PROTOCOL TEST WORKER, no real model profile); nothing from a request or a result is executed or appended to argv.
- Exchange: the request goes on stdin as canonical JSON, the result comes back on stdout, stderr is diagnostics. Both streams are read concurrently and capped, time is limited, and the child is killed on overrun.
- Persistence per delivery: store/<delivery_id>/request.json; launch.json, written by exclusive create before the launch; attempt/{stdout.bin, stderr.bin, exit.json}; receipt.json, written atomically last.
- Idempotency: an identical repeat returns the stored receipt marked replayed; changed contents under the same identity are refused; a launch without a receipt is uncertain and is never relaunched.
Demonstration: `python -B run_demo.py evidence/demo-run-01`. The prepared request goes to `bridge.cli deliver` in its own process; the fixture reads input/input.txt and writes output/result.json ({"count":3}); the adapter correlates the identities and verifies the artifact bytes inside the output root; a fresh process (`bridge.cli status`) reads the receipt: transport delivered, claimed outcome done, collection collected, worker kind protocol test worker, review not performed. Trace: evidence/demo-run-01/trace.md.
Confinement: a same-user subprocess with no OS sandbox, no network control, and only the direct child killed (no process-tree kill on Windows). Path checks prove where artifacts are, not what the process could touch. The receipt is lab transport evidence, not a ledger. No kernel or runtime module was seated or executed.
