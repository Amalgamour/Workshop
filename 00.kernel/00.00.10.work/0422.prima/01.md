## Transport and loop
Prime publishes only on prima/assignments. Prima publishes only on prima/returns,
using explicit allowed paths and a Model: trailer. No automatic merge or deletion.
Both branches initially share the same prepared snapshot. No local D: access is
available to a cloud bot. Source code may exist elsewhere in the inherited tree;
only the pack's declared files/commands are in pilot scope.
Every two hours check assignment discovery. Save a read-only source checkout at
the exact observed commit and run input verification before execution. The job key
is assignment id plus pack hash. Existing claim, partial or final return for that
key prevents a new run, even on another poll or reset. A changed hash under the same
id is a conflict: stop that job and ask Prime for a new pass. Do not silently retry.
Record claim on prima/returns before delegating. Claims record id, pack hash,
assignment commit, worker roster, environment and start time. No reliable claim
publication means stop before starting workers; return the access problem.
Do not merge assignment branch into returns automatically: fetch exact inputs into
a separate read checkout. After a final return, stay idle for that job key. Polling
continues but unchanged checks stay quiet. Completion, blocking and new questions
may notify. One infrastructure retry requires recording the first failure and a
specific changed condition; no repeat loop on a product failure.
