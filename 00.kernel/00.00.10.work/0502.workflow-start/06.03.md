## Inspection contract (decided before code)
C01. Resolve the --revision once with `git rev-parse --verify <rev>^{commit}`. Every later read uses that SHA: `git ls-tree -r -z <sha> -- <book>` for the tree, and `git cat-file blob <sha>:<path>` for files. Nothing is read from the working directory or the index. All Git calls run with GIT_OPTIONAL_LOCKS=0, so even a read does not refresh the inspected checkout's index.
C02. Pointer: the book's 00.md must contain exactly one occurrence of the documented local sentence form `contents in <path>.`, where <path> is book-relative, starts with `0011.contents/` and ends `.md`. None, several, or another form is a refusal (exit 2). There is no fallback to 01.001 and no "newest" rule. `--contents <book-relative path>` inspects a named candidate instead, and the report says the selection source was the command line, not the sentinel.
C03. Supported contents structure (the one write_contents.py emits, and the hand candidates copy):
- a "## Pages" section with the header `| Page | Faces and files |` and its separator;
- one row per page: `| \`PPPP.title\` | entry, entry, ... |`, where each entry is `` `name` `` (a direct file) or `` `name/` (N files) `` (a direct subdirectory with its recursive tracked-file count);
- `Book files:` followed by back-quoted names and a final period;
- `## Other books` followed by one line of `Label: \`relative path\`.` items. These paths are resolved relative to the book root (write_contents.py's convention; relative to the face itself they would not resolve), lexically, and must stay inside the repository.
Any other row shape inside the Pages table, or a missing section, gives "unsupported structure" (exit 2), never a pass.
C04. Checks: page rows against the tree's direct page folders (missing, extra, duplicate row, duplicate page number with different titles); per page, the direct files and direct subdirectories (missing, extra) and each directory's recursive tracked-file count; the book files listed against the files at the book root; each Other-books path present in the tree as a blob. A finding is advisory. Exit 0 clean, 1 findings, 2 invalid input, unsupported structure, or tool failure.
C05. Out of scope, stated in the report: prose references, links outside the two declared lists, page faces' content, whether a page "should" be published, and anything in the working tree. A clean result means "the selected contents describe the published tree at <sha>", nothing more.
