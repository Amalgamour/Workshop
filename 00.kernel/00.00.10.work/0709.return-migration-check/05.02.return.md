## Proposed enforcement and pin changes, exactly
1. **The stop for unchanged R1 (zero code and zero pin change).** Write a sentinel `0100.band.returns/.allocation.lock` with fixed bytes (`GROK1-05-DRAFT.md`).
   - pass01 `allocation_lock` opens the lock with `O_CREAT|O_EXCL` and refuses after 5 s: "allocation lock held". It never removes a lock it did not create (return_capture.py 32, 368–388).
   - **H4 showed:**
     - a new reserve: exit 2;
     - a repeat of an in-flight reservation: exit 2 (the idempotent "already-reserved" answer is lost);
     - in-flight `capture`, `verify` and `inspect`: exit 0;
     - the lock bytes are unchanged.
   - It is written live **only** at cutover step 1, by Prime, under the release.
2. **The supported route.** Grok-1 builds NEW `app/return_line_tools_v2.py` and registers it in `librarian.py`. It pins Grok-2's pass02 and keeps the helper and inspect for reading.
   - Its phase gate (sequential, frozen, line-pass, inconsistent) refuses line writes unless both the layout and the sentinel are present. Lookups always work.
   - No stage, publish, retire or rollback through the app.
   - **Unchanged:** `handoff_tools`, `boot_tools`, `batch_tools`, the pass01 door, and the bytes of every lab.
3. **Rejected: a guard edited into `return_capture.py` itself.**
   - Its sha 8f3da5c6… is pinned in **109 non-evidence files**: 8 in `app/`, 22 lab directories, `return_lines.py` itself (`READER_SHA`, line 44) and sealed custody returns.
   - A staged update would need a pass02 helper, re-pins in `return_lines` (and so in its own pinners), three app doors, `handoff.py`, `prime_boot`, `batch_observe`, and the 0525 declarations. That amounts to the global pin refresh the pack forbids.
   - The sentinel reaches the same supported-route stop with none of it. **If the sentinel is judged too fragile, that staged list is the cost of the alternative.**
4. **Confinement statement.** None of this confines arbitrary same-user code. Anyone can delete the sentinel, `mkdir 0126.x`, or call an old function in-process.
   - The contract covers the supported routes only: the 0100 text, the app door and the pinned CLI.
   - **Deletion is detected, not prevented:** the status phase becomes `inconsistent`, which refuses writes through the v2 door.

## Factfind
- **The real gap is not a missing preferred command.** It is that the operative instruction points at pinned code which ignores the declaration and even re-creates the door, which then disables the line tool.
- **The cheapest honest stop is the helper's own lock refusal.** It needs no pin change.
- **The cheapest honest legacy read is a book-shaped archive** that keeps the old names, because every reader already takes `members_book`.
- **My opinion:** build Grok-1's slice now with the C-tests stubbed. Release the cutover only after Grok-2's contract and a rehearsal with the door present. Keep the freeze short by preparing the staging rebuild before T0, and rebuilding it again after T0 only if the audit changed.
