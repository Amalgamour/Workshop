# Notes before the Prime-cycle design

Date: 2026-10-30. Author: Codex Prime.

The Director agreed that compute should close the read, review, record, read loop
and explicitly show what is completed. The Director then approved the sequence:
Claude builds and tests; current Prime uses it on actual work; a separately started
cold Prime performs a contextual Colab; bounded corrections follow. The latest
instruction is to pack for Claude, not to launch a model or transfer this desk.

Preserve the distinction between finishing one pass and completing a work-page
goal. A successful capture, acceptance of a correction and a green test suite do
not independently complete a goal. Preserve Director-input holds and unknowns.

Use the existing tools. The missing part is recording Prime's exact attributed
judgment beside its work, then automatically deriving the next view from it. Do
not create another manually maintained status story. A read should also prepare
the mechanical fields of a review request so Prime supplies judgment rather than
recopying hashes, member identity and coordination arrays.

The two-operation interface is a target, not a reason to rebuild Clerk, all boot
code, capture or the app. Start with one book and explicit registrations. Require
support for reading the real work book; do not repeat a disposable-only interface
that cannot later be used by Prime. Builder mutation remains disposable; later
Prime writes require a caller-declared, bounded work-page review location.

Readback: design below accounts for scope, existing dependencies, recording,
completion, interruption and trial sequence. No current desk migration, historical
release authentication, AR-01 clearance, model/API call or automatic dispatch.
