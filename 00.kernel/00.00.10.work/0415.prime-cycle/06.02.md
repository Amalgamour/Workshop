# Process discussion — three loops and the first complete route

Date: 2026-10-30. Author: Codex Prime.
State: discussion draft. No amendment to Claude's released 0515/05.01 pack.

## Director request

The Director identified development on N4NN, a work-pass loop and a Colab loop,
and asked to choose one loop to make functional with compute handling as much of
the mechanical work as possible. The tool should be comfortable for a model to use.
Prime proposes the work-pass loop first. This is a proposal for discussion, not
an instruction to the active Builder or an invented Director decision.

## Development loop — N4NN

Explore a need -> preserve words and questions -> clarify intent, boundaries and
choices -> record decisions/reasons -> produce a bounded work statement or a Colab
question. Keep undecided proposals and overflow visible. Compute preserves and
formats; intelligence develops the idea and distinguishes talk from an instruction.
Exit: an agreed scope and finish criteria, a named unresolved decision, or a clearly
parked idea. Discussion alone is not execution release.

## Work-pass loop — N5NN with N1NN custody

Start with an already agreed work-page goal and explicit grant. Prime supplies one
bounded pass. Compute formats instructions, binds sources/dependencies, identifies
executor/reviewer and reserves the exact return route. Release/claim are explicit
records; neither a formatted pack nor a reservation grants them.

Builder performs the granted work, with checks from that pack, and captures exact
return/artifact bytes. Compute validates supported custody and mechanical bindings
and gathers review evidence. Do not execute commands merely because a return
contains them. Prime judges outcome and alignment, then supplies the disposition,
findings, reasons, pass completion, page-goal completion and one next action.

Compute records that judgment beside the work, preserves predecessors, regenerates
the desk view and produces the next permitted handoff from Prime's recorded choice.
It does not choose the route. Existing declared publication/launch policy controls
transport. Local capture and Git publication remain separate visible facts.

Continue: another bounded pass inside the existing grant. Director-input: hold the
affected action and preserve the exact question/reply. Develop: return to N4NN for
a real design issue. Complete: explicitly finish the pass and separately identify
whether the page goal is complete. Green tests/acceptance/publication alone do not
set either terminal declaration. Two reviewed unresolved passes follow elevation.

Shared identity: one work page, named pass, source cut, exact return/receipt and
bound review. Avoid an independent status ledger. Derived indices and 00.live
candidates point to the work-local record. Interrupted writes remain partial;
identical replay changes nothing; conflicting/stale input requires reconciliation.

## Colab loop — N7NN with N1NN custody

Name the uncertainty -> supply purpose, built state, question, exact targets/sources,
permissions and known gaps -> compute prepares the package -> Colab investigates
and preserves Hostile/Factfind/Overflow/Unprompted observations -> capture exact
return -> Prime answers each finding: fix, answer with reason, or elevate.
Exit: an answered question with findings dispositioned, an explicit further Colab
pass, or a linked development/build action. A Colab return is not implementation
acceptance. The N7NN exchange remains pack/return/notes/review with shared pass NN.

## Shared desk entry and checkpoint

All three loops need a reliable entry: what arrived, what is open/held/complete,
what sources were examined, and the recorded next action. They also need a durable
checkpoint so a later session can recover the same state. This is shared desk
support, not a fourth permission to execute conversation or automatically select work.
Incoming-chat capture/attachment remains a named future input gap.

## Proposed first route and boundaries

Close one work-pass route first: granted pass -> exact return -> review -> recorded
outcome -> next read shows the same result and recorded handoff. Use the current
Prime-cycle adapter for the read/record connection. Existing pack/capture/review
helpers handle their parts. Active Claude work stays within its pinned assignment;
this draft is not an unannounced new acceptance requirement.

First demonstration: one return needs correction; the next pass resolves it; each
pass's outcome and the whole page's completion remain distinct. Include a Director
hold contrast. Stop/restart the command process and recover the state. Current
Prime uses it before a cold-Prime contextual Colab. Do not promise automatic model
launching, transport integration or a universal factory line in this first slice.

## Comfortable tool behavior

Prime supplies goal, judgment and exceptions once. Compute carries addresses,
source/receipt identities, prior-state bindings, formatting and destination rules.
Read returns ready mechanical review fields plus a compact evidence menu. A result
names completed work, retained partials, holds/unknowns and the exact allowed next
operation. Missing data produces a specific correction request, not an empty error.

Explicit operation names, one small stable request shape, useful failure evidence,
idempotent repeats and safe new attempts matter more than the number of commands.
No repeated copying between the same fields in several tool formats. Preserve exact
Director words and unresolved reasons at their work-local landing. A successful
mechanical check never substitutes for a semantic judgment.

## Observation during actual use

Keep a short friction log: each manual lookup, copied value, repeated explanation,
missing connection, confusing refusal and necessary judgment. Mark which are
mechanical candidates and which genuinely need intelligence. Do not call an awkward
route smooth because Prime quietly bridged it in conversation. Measure only actual
operations/effort; this draft establishes no savings or model performance result.
