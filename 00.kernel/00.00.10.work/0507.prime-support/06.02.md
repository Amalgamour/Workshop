## Missing machine-readable fields
G01. Execution state on the Return section: inconsistent (S02). Proposal: one line `execution: claimed|running|returned|stopped` as the first line of every new Return section. Without it, status shows `unknown` and never parses prose.
G02. Review-to-revision binding: `Reviewed return SHA-256` is the whole page as it stood at the return commit (R01). It breaks as soon as the Review section is written. Proposal: Prime also records `reviewed_return_prefix: <sha256>` (defined in R01). Intake matches either one.
G03. Findings in a Prime review are prose (BRI-01, OR-01, CR-01…). Observer reviews have tables (06.02:112-118). Proposal: Prime reviews end with one line, `findings: <ID>=<resolution>; …`, using the 0505 resolution words. Without it, status shows `findings: not machine-readable` and never guesses.
G04. Dependencies are prose (Independence sections, waits_on). Proposal: an optional `depends_on: <path>[ + <path>]` line in a new batch's Assignment. Without it, `dependencies: unknown`.
G05. There is no lane registry. Proposal: a Prime-written `lanes.json` that owns paths and scope only (DESIGN §2).

## Rules derived while designing
R01. Return revision identity is sha256 of the page bytes from the start of the file up to, not including, the first line that begins `## Review`. Tested on pinned history:
- 0504/05.05 prefix 8c1dfe6f… is identical at the return commit cf25d56 and after Prime's review at 2c581eb (whole file 56c4e2c1… → 5a52d9e9…).
- The Builder's amendment d9775fa → cf25d56 changed the prefix (25ca0e6d… → 8c1dfe6f…).
- Prime's recorded "Reviewed return SHA-256 56c4e2c1…" is the whole file at cf25d56.
- So an appended Prime review is not a new return, an amended return is a new revision, and the historical whole-file hash still maps to exactly one prefix.
R02. Not every file edit is a pass. A pass is one reviewed return revision in a finding's lineage (0505 §4). Observer polls and Prime notes are not passes.
R03. Acknowledging intake ("seen") is a Prime act recorded by intake. Review status and findings are derived from the page-local records. The intake store keeps acknowledgements only.
