# Prime seed notes — 2026-10-27

## Director intent
Usage is currently leaky while compute is incomplete. Build Prime-support modules
before replacing Prime. A future Prime should first run under Codex observation,
with responsibility expanded through reviewed evidence, not immediate full control.
Director requested Claude as designer for this next work.

## First priorities
Status: declared lanes, owners, exact assignments, source revisions, blockers and
returns awaiting review. Intake: new returns and immutable Observer notes, with
durable review/disposition tracking. Assignment preparation and handoff readiness
are subsequent modules; design their boundary, do not bundle all four into v1.

## Problems the design must face
One global assignment record currently describes only the app lane. Parallel
Clerk work is explicit on its own batches. SoF is a separate repository. Directory
mtime is not execution state, a role is not authenticated by --as, and historical
draft headers can coexist with an appended returned execution record.
Mutable return files gain Prime reviews: a new whole-file hash alone cannot mean
a new Builder return. Some recorded evidence commits precede final return commits.
Observer notes are immutable advisory files on observer/reviews; their external
two-hour check schedule does not make our intake automatic or grant action rights.
No model should scan the entire imported source tree merely to orient itself.
The current context is not a permanent registry of active workers.

## Boundaries
No competing Clerk queue or duplicate editable job-state store. A small discovery
registry may own paths/scope only. A review/intake record may own its own disposition
state, with references to the returned source and actual decision; it must not
invent acceptance. Findings remain page-local with why and response history.
Status must expose unknown/stale/conflicting facts rather than guess them away.
Keep proposed identity/status-field changes distinct from existing implemented law.
Do not create a new universal grammar or modify kernel while designing this.
