## Correction contract (additive; DESIGN.003 records it)
C01, binding: a review item is VALID only if its target revision is a known revision of its declared target lineage. Known means a revision id of the target path seen in bounded history or among the observations.
- A page Review targets its own page.
- A review source must declare `reviewed_return_path: <registered page or return file of the same lane>` and `reviewed_return_prefix: <64 hex>`. The target is never inferred.
- A legacy `Reviewed return SHA-256` is valid only when that whole-file hash equals an observed version of the same path.
- Otherwise the item is `unknown-hash`, `invalid-legacy`, `invalid-target` or `unbound`. It stays visible, with its source and its finding text, as attention. It never changes a finding or counts as a pass.
C02, scope: a finding's identity is (target path, ID). The same ID on two pages is two findings.
C03, causal order:
- Committed records for one finding are compared by `git merge-base --is-ancestor`, never by timestamp.
- The frontier is the set of records whose commit is not an ancestor of another record's commit.
- One resolution on the frontier gives that state. Different resolutions on the frontier give `conflict`, every record is shown, and it is an attention item.
- There is no timestamp, registry or lexical winner.
- Records on the same commit with different resolutions also give a conflict.
C04, uncommitted:
- A worktree file whose bytes equal HEAD's is the same observation, not a new one.
- A differing worktree file is a `draft`. Draft resolutions are reported apart from the committed state as `draft`, and never replace it.
- A draft that differs from the committed frontier is attention, `draft differs`.
- A finding seen only in a draft has state `draft-only`.
C05, passes = distinct target revisions bound by valid committed reviews that mention the ID. Repeated copies of the same review across commits, or an identical worktree, add nothing.
C06: history ordering for `supersedes` uses `git log --topo-order`, not timestamps.
