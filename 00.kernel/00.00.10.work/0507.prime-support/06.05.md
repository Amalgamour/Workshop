## Decisions
D01. Registry version 2. Version 1 files keep their exact shape and meaning.
- Version 2 adds an optional top-level `clerk_tool: {path, sha256}`.
- Each lane gains an optional `clerk_jobs: [{store, job_id, instructions_base, reviewer}]`, every path absolute.
- A version 1 file that uses either key is refused (unknown key).
- `clerk_tool` is required when any lane has clerk_jobs.
- The registry owns paths and scope only.
D02. Code identity:
- The adapter holds the accepted hash as a constant, ACCEPTED_CLERK_SHA256 = f697a7e4…. The registry's sha256 must equal it, and the file at `path` must hash to it immediately before each run.
- The caller cannot choose other code.
- Execution: `[sys.executable, "-I", "-B", <path>, "show", "--store", S, "--job", J, "--instructions-base", B, "--json"]`, with no shell, cwd set to the system temp directory, and a timeout.
- The gap between the hash check and the launch is a same-user race. It is stated, not solved.
D03. Strict parse of inspection/2 (strict JSON, exact keys, enums, types), with the exit code checked against `problems`. Anything unexpected is an `unsupported` attention item, never success.
D04. A distinct subject kind `clerk-return` with subject `{kind, store (normcase realpath), job_id, event_sha256}`.
- It is stored as a `prime-intake/2` record. `prime-intake/1` records are read as before, unchanged.
- The id12 directory rule is the same.
D05. Eligibility and cleanliness:
- **An identity** exists only when state is `returned`, `returned.event_sha256` is 64 hex, `checks.events` and `checks.completion` are `ok`, and the binding holds (job.job_id and job.reviewer equal the registration).
- **Clean** additionally requires `checks.artifacts ok`, `checks.instructions usable`, empty problems and exit 0.
- A nonclean but intact return can be acknowledged as seen. It stays a `clerk-not-clean` attention item for as long as it is nonclean.
- A binding mismatch is a `conflict` and is not acknowledgeable.
D06. Review status of Clerk returns is `not-machine-readable`. No review is inferred from the event, the acknowledgement or the projection.
D07. `intake ack-clerk` is a new subcommand. It freshly inspects, requires the given full event_sha256 to equal the observed one, then performs one exclusive write in the intake store.
- The intake store must lie outside Git, and outside every registered Clerk store.
- Nothing is ever written to a Clerk store.
D08. The adapter reads no store file itself and does not enumerate jobs. Tests prove this by recording every in-process file access during adapter calls and asserting the exact argv.
D09. Not built: whole-inbox discovery, queue/claim/return in the adapter, a real registry or store, app wiring, Observer fetch.
