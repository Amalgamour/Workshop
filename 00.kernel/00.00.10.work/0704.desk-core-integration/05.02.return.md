## 3. Remaining findings and decisions
- **R1 (Prime, technical) — Relocation would stale reviews.**
  - `review-task-binding/2` hashes the receipt's placement, member and page-local name (0522 CONTRACT RC-03, pack05.01 snapshot 0015).
  - So a review of a legacy-in-place or staged return goes stale when the bytes are merely relocated to their final line. That contradicts "relocation is preservation" (policy A1) and "freshness on read" (Prime F8).
  - **Proposed:** relocation equivalence. A difference only in location fields, linked by a verified relocation record with an equal receipt hash, reads `current-via-relocation`.
  - **Alternative:** a later binding/3 without location fields. Not proposed now, because 0522 is active.
- **R2 (Prime → 0521, when 05.03 returns) — A staged seal can only relocate by byte copy if its receipt and manifest do not embed their own path.** This is a requirement to carry, not a change to the active pack. Unverified: `return-line-capture/1` is not in the packet.
- **R3 (technical) — v2 must be a new schema identifier.** v1 uses exact keys, so /1 consumers refuse any added key. /2 consumers read /1 as final placement. Active builders keep v1.
- **R4 (Director, DC3, the only open choice).**
  - *Effect of leaving it undecided:* the typed successor record (supersedes, verbatim question-bound answer) can exist, but no renderer may overwrite or append a substantive review. It refuses with `route: escalate — DC3 successor layout undecided` and keeps both texts.
  - *Prime's recommendation:* same-home succession. For N7NN that home is `06.NN.review.md`.
- **R5 (Prime, technical) — Staging location.**
  - *Proposed:* `<source page>/evidence/return-staging/05.NN/sMM/`. It is work-local, its name says staging, it sits under evidence and not on a return line, and each seal is a version. The policy approves staging; the exact path is technical.
  - *Alternative:* a book-level staging folder. Rejected, because it scatters work away from its page.
- **R6 (Prime) — No recorded format exists for an explicit solo delegation.** The proposal requires `grant_ref` to point to a recorded Director delegation. Without one, the mode is `normal`. No grant is created here.
- **R7 (accepted limit) — `report.status delivered` is Prime's own statement plus the exact report text kept on the page.** It cannot prove the Director read it, which is consistent with policy. No read receipt is invented.
