## Design observations (to carry into the proposal)
- **O1. Binding across relocation.**
  - 0522's `review-task-binding/2` preimage includes the receipt's placement, member and page-local name (pack05.01 snapshot 0015, CONTRACT RC-03).
  - A legacy-in-place or staged return later relocated to its final N1NN line therefore changes the binding. A review made before migration would read stale after a purely mechanical move. That contradicts P7 and A1, which say relocation is verifiable preservation, not new material.
  - **Proposal:** a declared relocation-equivalence rule. A stale result whose only differing fields are location fields, linked by a verified relocation record, reads as `current-via-relocation`.
  - **Alternative:** a later `/3` preimage without location fields. Not adopted here, because 0522 is active.
- **O2. The staged seal's identity must not change when it is relocated.**
  - Whatever 0521 defines as `return-line-capture/1`, its receipt must not embed its own physical address. If it does, a staged→final copy cannot keep its receipt hash.
  - This is a requirement to pass to 0521, not a change to its active pack. I cannot verify it: the schema is not in the packet.
- **O3. Versioning.** Seam v1's descriptor has exact keys, so a /1 consumer refuses any extra key. v2 must be a new schema identifier, and consumers accept both. v1 descriptors stay valid for final placements.
- **O4. Reporting state is not seam custody.** It belongs to the Prime review record and page. It sits in the proposal as a separate section that consumes the seam, so the seam itself stays a custody and descriptor contract.
- **O5. Holds.** Unrelated work must not be blocked. Holds list `dependent_scope` action ids (the existing prime_review semantics). The examples must show an unrelated action proceeding.
