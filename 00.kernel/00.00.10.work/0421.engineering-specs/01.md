date: 2026-11-01
who: Codex Prime
state: future deliverable requested by Director; not implemented or released

## Purpose
A reusable seated 05 states what a module must do, how its declared connectors
join other pieces, and what evidence proves the specification is met. Builders
choose internal functions, algorithms and language unless an explicit requirement
constrains them. Historical implementations are references, not accidental law.
The 05.NN passes retain experiments, decisions, failures and refinement history.

## Expected specification contents
Purpose and observable behavior; exact connector names, input/output schemas and
meanings; dependency identities/contracts and links to workflow/why; supported
environment and capacity targets where material; preservation and authority
boundaries; failure/recovery behavior; acceptance tests and expected results.
Label mandatory requirements, optional examples and proven reference methods.
Keep selected specification revision explicit and differences traceable.
Compute should validate mechanical completeness, assemble focused packets and
run applicable checks. Intelligence owns design, interpretation and exceptions.
A comprehensive spec can be retrieved in bounded parts; it need not all load into
model context every time. Do not lose the reasons that justify a constraint.

## Acceptance direction for a later bounded build
Given an approved spec and declared dependencies, a builder can implement a module
without reconstructing its interfaces from chat. Tests inspect required behavior
rather than mirror one implementation. A second implementation can use the same
connector contract and test suite. Missing/contradictory requirements are reported,
not guessed. A passing test suite proves only its covered requirements, not semantic
completeness or Director approval. Preserve specification/build/test provenance.

## Scope and sequencing
Later work after the current Prime desk/review loop is used. No language migration,
local-model selection, rewriting old artifacts, watermark removal claim or new
kernel law follows from this page. This records engineering practice as a workshop
deliverable. A future N5NN pack will define schema/tools and acceptance fixtures.
