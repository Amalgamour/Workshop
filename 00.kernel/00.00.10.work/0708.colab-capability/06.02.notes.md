## Method

Locked before any pass02 code or probe.

The successor is colab/labs/0708.colab-capability/pass02/probe.py. It is a run allocator and status recorder. It does not prepare a package, does not check a handoff, and does not open a workflow book.

There is no default evidence root and no default scratch root. The operator passes both as absolute paths of directories that already exist. The probe does not create those roots. A run id is one path segment, or it is omitted and the probe allocates `run-YYYYmmddTHHMMSS-` plus random hex by exclusive creation, retrying on collision. An explicit id that already exists is refused.

The evidence slot is created with `os.mkdir`. That call fails if the destination exists. The refusal writes nothing, including no scratch slot, even when the occupied contents look disposable. The probe never deletes a directory and never reuses a slot.

After the evidence slot exists, the probe writes `command.json`, `inputs.json`, and `status.json` with flush and fsync before any child work. The first status is `running`, and its interruption is null. That file is the incomplete marker. A final status is written with `os.replace` only by the same process. A later process cannot enter the slot, so it cannot mark the earlier run successful.

Scratch is then created with exclusive `os.mkdir` under the scratch root, using the same run id. If that destination is occupied, the probe does not touch it. The new evidence slot records status `failed` and interruption `caught-failure`.

Modes:

- `ok` runs a synthetic child that writes `minimal-ok` and exits 0. Status `complete` and interruption `none` are written only after the exit and the output bytes match.
- `fail` runs a synthetic child that writes `partial-output` and exits 1. The partial file stays. Status is `failed` and interruption is `caught-failure`. This mode has no success status. The label is controlled failure.
- `hold` writes the running marker and then sleeps. The harness kills that process. Status stays `running` with interruption null. The label is actual termination. If the sleep finishes, the same process records `failed` / `caught-failure` and does not record success.
- `preview` is the one existing-tool path. It reads the producer file and requires sha256 `2b720434ac4c4331835c1484b0eca362e01e8afbecde0ab800ca392530abf68b` and 53892 bytes. A mismatch is recorded in the new slot and the producer is not started and not edited. A match runs `preview --request --config --json` on the unchanged producer. Success requires exit 0, schema `colab-support-report/2`, result `preview`, and a 64-character digest. Otherwise the slot keeps the child output and records a caught failure. There is no second preview.

Exit 0 means the status file says complete. Exit 1 means this process recorded a failure in a new slot. Exit 2 means a refusal before an evidence slot was created.

Schema names: `colab-probe-command/0502`, `colab-probe-inputs/0502`, `colab-probe-run/0502`.

The child code is a fixed literal in the probe. Fixture text and packaged source text are not executed. Preview passes file paths to the existing producer, which reads them as data.

## Limits already accepted

No power-loss durability is claimed. Flush and fsync are what the running marker does; a kill during `os.replace` is not a tested case.

No general concurrent-race freedom is claimed. The harness may show one same-id pair where exclusive creation admits one process and refuses the other. That is one observation.

No authenticated ownership is claimed. The slot records the command, the interpreter, and the input hashes. It does not prove who launched it.

A `running` file left after the process is gone is an incomplete marker. It is not rewritten to success by a later run. It is also not proof of the operating system's process table.

The preview check is a wrapper invocation of the unchanged producer. It is not package acceptance, not a review, and not an 01.003 implementation.
