## Outcome
Open a desk and recover where work stands without reconstructing yesterday's chat.
Three layers: short overview; selected-task working packet; underlying book and
history available on demand. Compute assembles/verifies; Prime supplies judgment.
Books are the environments. Address names a location within the selected instance;
repository/book instance and source revision/hash disambiguate copies. Never mix
same-address records from different book instances silently.

## Overview - required fields
1. Context and purpose: selected desk/book instance/role, goal, finish criteria,
   scope and authority references.
2. Current work: exact explicitly selected page/pass, last recorded checkpoint,
   last verified result, and supplied/recorded next action. Do not select newest.
3. Attention: Director questions, returns awaiting review, Observer findings,
   conflicts, missing evidence, interrupted operations. State declared coverage;
   unregistered does not mean none. Local Observer references only, no polling.
4. Workers: exact declared assignment and last evidenced released/claimed/returned/
   awaiting-review state. Chat assertion is attributed supplied evidence, not proof
   that a process is currently running. Unknown activity stays unknown.
5. Available operations: exact installed tool/contract/dependency identities and
   their reviewed limitations. Existence, pin validity, past tests and activation
   are separate; never execute arbitrary operations to discover capability.
6. Record: recent relevant instructions and decisions, exact wording/attribution,
   reason and source links. Discussion is distinguishable from released command.
7. Inspectability: source/time/hash, verification or claim basis, freshness limits,
   correction/help/escalation route and drill-down references.

## Selected-task packet
Exact assignment and finish criteria; applicable scope/authority and Director
replies; return and declared deliverables; real verification results; prior
findings/dispositions; relevant dependencies/rules; correct review destination
and recorded next routes. Expand exact source on request; bounded overview must
not quietly truncate open holds or contradict selected task. No model-generated
judgment or guessed resolution. Compute cannot classify arbitrary chat as command.

## First slice and measurable finish
A read-only standard-library CLI emits Markdown and JSON from explicit registered
sources. Reuse the reviewed desk-state/brief/status readers where applicable;
explain gaps instead of cloning their lifecycle semantics. Initial hand-maintained
reference catalog is an index, not a duplicate authority store. It may contain
attributed supplied labels, but selected task text and decisions live at sources.
Changed source hashes show stale references with evidence; no silent repinning.
One view -> expand one selected work item -> new-process view must recover the
same identity and exposed unresolved items. Default short view targets roughly
30-60 seconds reading; report overflow counts and explicit expansion routes.
No hard budget may conceal an affected hold. No full-repository crawl each call.
Success means Prime actually uses it on the working book after review, identifies
current work and limitations, and records manual steps still needed. A synthetic
suite alone is not that finish. This is a development read view, not seated 00.live.
