## Identities

Accepted intake rows are built with bytes, declared_bytes, declared_path, declared_sha256, path, role, root, and sha256. A current read of the 0522/05.13 intake found 32 row objects and only those keys. None is a physical-file identity. The successor does not stat, list, open, or re-hash those paths, and it does not read declared_path as an identity.

Addressed source paths are exact root-string plus path-string pairs. Repeated roles on one pair share one addressed source. The same path string under two root strings is two sources. There is no slash folding, no case folding, and no dot-segment resolution. Bytes add each address's agreed int size once. A missing root or path leaves the whole addressed total unknown. A size disagreement leaves the count measured and the bytes unknown.

Content-blob identities are 64-character lowercase sha256 values. A hash proves content equality only. The two disclosed files are one content blob of 4 bytes and two addressed sources of 8 bytes. A row without that hash form leaves the whole content total unknown. Conflicting int sizes for one hash leave the count measured and the bytes unknown.

Verified physical-file identity stays unknown. The reason is that accepted intake metadata has no physical-file identity, and a path plus a content hash do not establish one. The successor does not claim a hard link.

Declared entries, measured artifact-role rows, and intake role rows keep their pass02 scopes. The successor schema is review-report/3. The unique_files field is not emitted.
