## Where the identity already exists
K01. _apply_completion() (clerk.py, before :551-608):
- it reads 0003 once (`returned_bytes`);
- it compares sha256(returned_bytes) with the witness digest, and stops as incomplete on a mismatch;
- only after every check passes does it append `(RETURNED_NAME, sha256(returned_bytes), claimed_sha)` to `view.events`.
That digest is therefore exactly "the returned-event bytes validated against the witness". Using `view.events[-1][1]` adds no second reader and no reread.
K02. A projection is `returned` only when the view status is returned and it is not structural (before :1229-1238). Incomplete or corrupt views carry null `returned`, so they can never supply an identity.
K03. A changed artifact does not touch view.events: inspect_artifacts reads only the outbox. The event identity therefore stays the recorded one while checks.artifacts says `changed`.

C03. README consumer contract:
- exit 0 means a structurally valid projection;
- `instructions: not-checked` is not verified and not ready;
- a consumer that needs usable instructions passes `--instructions-base` and requires `usable`;
- a clean returned handoff requires state `returned`, events, completion and artifacts `ok`, and empty problems; state alone is not enough;
- an observation of a troubled record keeps its diagnostics;
- the tool grants no approval.
