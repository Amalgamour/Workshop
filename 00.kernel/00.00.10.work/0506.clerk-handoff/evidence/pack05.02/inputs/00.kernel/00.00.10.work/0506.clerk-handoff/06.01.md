## Clarifications to proposal sections 3-7
1. Use a versioned exact-key local JSON schema, strict types and Windows-safe IDs.
   Reject ambiguous/case-colliding IDs, nonfinite JSON, traversal and unknown keys.
   Name the instruction-path base explicitly; verify its hash before queue/claim
   and before exposing it as usable instructions. Never locate it via ambient cwd.
2. Expected outputs are distinct simple relative filenames in outbox for this
   slice; no nested directory grammar. Require ordinary files, no symlink/reparse
   aliases and link count one. Every mutation uses exclusive creation and preserves
   existing data. No claim that these checks defeat a malicious same-user race.
3. Add explicit resume: a claimed job remains discoverable to its recorded
   assignee; claim --resume (or an equally explicit documented read operation)
   returns the SAME existing token without appending an event or creating outbox
   again. Ordinary second claim still refuses. No lease, reassignment or retry.
4. An interrupted queue/claim/return must never look complete or be auto-reset.
   Exercise at least interruption during event publication and between claim and
   outbox setup. Either provide a small deterministic completion protocol or
   refuse as incomplete/uncertain with an explicit diagnostic. Do not delete
   records, silently reclaim, create another token, or grant a reviewer success.
   No general recovery engine is required. README states recovery limitations.
5. Define resend identity from the caller's return fields and verified artifacts,
   excluding newly generated timestamps/hash-chain fields. Same DID and identical
   content after a complete return is already-recorded: no event and no new time.
   Changed content under that DID refuses, including artifact changes. This is
   per-job idempotency; no global delivery namespace or exactly-once claim.
6. inbox must disclose corrupt/incomplete entries rather than silently omit them
   and imply an empty successful queue. Verify/show must clearly distinguish
   bad state from no matching job. A hash chain detects corruption; it is not a
   signed ledger and cannot authenticate an adversary rewriting the whole store.
7. No --allow-repo-store bypass in this slice. Tests/demo use external temporary
   stores. Refuse a store resolving into a Git working tree (including a .git file
   worktree marker); no code writes in the shared repository while demonstrating.
8. Test only the current scope. No scheduler, real model, automatic route choice,
   acceptance/closure, worker launch, app/bridge imports, SQLite or universal law.
   Claude may recommend routine implementation choices within this contract;
   proposed scope/authority changes return to Prime/Director, not a guessed rule.
