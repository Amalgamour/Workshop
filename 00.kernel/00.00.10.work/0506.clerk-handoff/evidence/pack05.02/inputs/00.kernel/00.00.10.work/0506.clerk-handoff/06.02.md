## Findings
CR-01, medium (a disclosed limit, but not fully stated). Deleting the last event after a return looks like a clean claimed job.
- To reproduce (P01): complete a return, then remove 0003.returned.json.
- Result:
  - The reviewer inbox exits 0 with "section returned / none", and verify exits 0 with "state claimed".
  - The same claim token can then return again under a new delivery id (P01b, exit 0), so a second, different return replaces the first without any trace.
- Conflict: 05.01 #03 asks that unexpected corruption never look like a clean empty inbox. The README (line 89) says only "no anchor beyond the last event". The 05.01 return mentions an unanchored *edit*, but neither names deletion or the re-return.
- No plain-file mechanism inside one store can anchor the tail without an external record.
- Recommended correction: say exactly this in the README and the return, deletion and its re-return consequence included, as a stated limit. No new mechanism in this slice.

CR-02, low to medium. OS errors escape as tracebacks with exit 1, which the CLI defines as "findings".
- Uncaught call sites: os.mkdir at clerk.py:728 (job dir) and :798 (outbox); os.listdir at :605 and :694; read_bytes at :645 and :844. None are wrapped. Only Refusal and Incomplete are caught.
- To reproduce (P04): make the outbox appear between the 0002 publish and the mkdir.
- Result: claim raises FileExistsError. The claim event is recorded, but the claimer is never told its token. Resume does recover it, and the later inbox shows a normal claimed job.
- Recommended correction: catch OSError in each command and report exit 2 with an explicit `incomplete:` diagnostic, so a crash can never read as "findings" or as success.

CR-03, low (test). test_git_store_and_unknown_flags_write_nothing assumes the lab itself is inside a Git working tree: it uses `LAB / "_not_created_store"` (tests/test_clerk.py:615).
- In a relocated copy, Clerk correctly queues there, and the test fails: `AssertionError: 0 != 2 : queued demo-0001`.
- In the shared checkout the case passes only because Clerk refuses a store path inside the shared repository. On a regression, the test would write into labs/ in the shared tree, against 06.01 item 7.
- Recommended correction: build that case in a disposable `git init` repository, as P05 does, so the suite passes anywhere and never targets the shared tree.

CR-04, low. `return --evidence ""` is accepted (P02; clerk.py:871 checks only the type). Pass01 refused a return with no evidence.
- Recommended correction: apply require_text to evidence, as is already done for release and routed_by.
- Related routine choice (06.03 asked for confirmation): refuse an empty expected_outputs list in this slice. A return with nothing for the reviewer to review is not a useful handoff, and the proposal's job always names outputs.

CR-05, note. evidence/build05.01/SHA256SUMS.txt uses CRLF line endings, so `sha256sum -c` cannot open its paths. All of its hashes match when checked directly. Writing it with LF would make the manifest self-checking. This is optional.
