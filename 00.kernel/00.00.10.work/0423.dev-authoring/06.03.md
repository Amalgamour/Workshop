## Proposed role
Face 02 is an explicitly typed working representation of the subject section governed by face 01. Its uses can include a card for retrieval, a template for construction, a schema for validation and existing permitted compute forms. These have different jobs; a short card must not be mistaken for a complete build template. The construction form tells compute how to request meaning, supply structure and produce a verifiable artifact without the model remembering layout or metadata conventions.

This proposal expands the operational account; it does not yet change the selected meaning of 02. Preserve lawful existing uses and investigate actual executable 02.filename forms before imposing a replacement. Do not declare a universal file extension, JSON language, Python runtime or workflow command in the kernel merely because the current prototype uses it.

## Minimum construction-template contract (proposed)
Identity: exact subject/page/section, form kind, version, state, governing source and intended output type. Sources: registered input notes/decisions, scope, source-to-work relation, applicable dependency/template references and declared inherited parts. Do not choose newest by filename or guess addresses.

Fields: name/job, expected data shape, required/optional/explicitly-not-applicable behavior, and whether supplied by intelligence, derived by compute or retrieved from a declared source. Preserve absent versus null versus empty distinctions where meaningful. A missing semantic value prompts for that value; compute does not invent it. Example values teach shape, never masquerade as actual Director decisions or default acceptance.

Assembly: declared header/stamp, sections, repeating items and footer; exact cross-reference rules; source/payload byte handling; allowed destinations. Numbering and paths are generated from the registered book/subject relation. Repeating #NN items are a pack-template use case, not necessarily universal to every face 02. Required and optional sections depend on the subject, not one giant global face list.

Dependency/readiness: declared module/resource/environment requirements and their source identities/conditions. Compute retrieves hashes/current records and reports missing/stale/ambiguous/conditional information. It does not prove undeclared runtime closure or compatibility from a digest. Changes to source/template/dependency/content invalidate relevant preview/review evidence.

Failure: field/source/check failed, observed versus expected shape, preserved supplied input and correction/help/escalation route. No silent section removal, encoding rewrite or source substitution. Input rejection is not rejection of the idea or permission to erase the work. Intelligence judges meaning; compute checks explicit contracts.

Review: whole generated artifact is inspectable, including source-note dispositions and unresolved choices. Prime reviews meaning against exact source/draft/template versions. Freeze/build/render is not release, approval, seating or locking. The lifecycle remains owned by its existing governing pages, with references rather than a second lifecycle inside 0002.

## Example: dev source to pack

Model reviews it; compute freezes exact reviewed inputs/output. Director release is still separate. This is the authoring prototype's instance of the general 02 contract.
