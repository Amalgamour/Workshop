## Contract

The product is `labs/return-capture-pass01/return_inspect.py`, command `inspect --book ABS --member NAME --json`. One named book and one named member. No enumeration, no queue, no allocation, no repair, no Git command, no network command, and no write.

The helper path is the sibling file `return_capture.py` next to the inspector. The pin is the constant SHA-256 above. There is no caller-selected path, no data file that chooses code, and no version fallback. The inspector hashes that sibling and refuses before import when the hash, the link bit, or the link count disagrees. That local pin gate is the only hash the inspector computes before import. Package hashes come from the imported helper.

After import, the inspector uses the helper's reader guard, strict JSON parse, reservation parse, and `verify_member`. It does not copy a receipt or hash validator and it does not parse the human verify text. `verify_member` is the integrity source. A complete observation may be built only from a successful `verify_member` result. `receipt_sha256` in that result is the helper's recomputation of `receipt.json`. It is not a field inside the receipt and it is not copied off a damaged file. Return hash and length are the values `verify_member` accepted by reading `return.md`.

Schema `return-capture-inspection/1` is defined in `evidence/inspection05.04/CONTRACT.md`. Top-level keys, exactly: `schema`, `book`, `member`, `status`, `problems`, `reservation`, `capture`.

`status` is one of `complete`, `reserved`, `missing`, `incomplete`, `refused`.

- `complete`: `verify_member` succeeded. `capture` is an object. `problems` is empty. This reports capture integrity only.
- `reserved`: the directory has a reservation the helper parsed, destination identity matches the folder, and the only files are `01.md` and `reservation.json`. `capture` is null. This is informational.
- `missing`: the member path is absent, or the directory has neither a reservation nor capture files. `capture` is null. This is informational.
- `incomplete`: the directory is readable and the helper's validator refused it, including a partial package, a bad hash, duplicate or malformed metadata, or a linked file inside the member. `capture` is null. A reservation object is included only when `parse_reservation` accepts it and the destination matches.
- `refused`: the helper pin failed, the book guard refused, the member name is not a return member, the member is not a readable directory, or the path escapes the book. `reservation` and `capture` are null.

Exit 0 is `complete`. Exit 1 is `reserved` or `missing`. Exit 2 is `incomplete` or `refused`. A well-formed `--json` invocation writes one canonical JSON object on stdout for every one of those statuses. Argument syntax errors stay on stderr with exit 2 and are ordinary argparse output.

`book` is the absolute path returned by the helper's reader guard when that guard succeeds. `member` is the requested string. Review, acceptance, seating, and publication are outside this schema. The object does not claim those decisions are false. `includes_prime_review` is the stored caller flag accepted by `verify_member`, not a review outcome.

A repeated read creates nothing. Disposable tests use a copy of the helper and members that copy creates. Live members, including `0110`, are not fixtures. The public `verify` result agrees with a complete observation by exit code, and its refusal exit agrees that every other status is not complete. The inspection status carries distinctions that `verify`'s single refusal code does not.
