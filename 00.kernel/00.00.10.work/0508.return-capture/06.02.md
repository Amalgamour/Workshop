## Contract — return-capture/1

Ordering is reserve, then local capture, then a separate Git publication. A receipt means the copy finished and the hashes match. It does not approve, accept, seat, publish, or finish the underlying work. Publication of a byte copy does not rewrite the sealed package and does not write its commit hash into `receipt.json`.

The helper is `labs/return-capture-pass01/return_capture.py`. Python standard library only. It does not dispatch the app, launch a worker, call a model, or choose a route. Labels and the recorded `release` string are stored text.

Commands:

```text
python -B return_capture.py reserve --book BOOK --submission ID --name SLUG \
  --origin-book BOOK --origin-page PAGE --origin-batch 05.NN \
  --expected-output LOGICAL --submitter LABEL --reviewer LABEL --release TEXT \
  [--supersedes 01NN.slug]
python -B return_capture.py capture --book BOOK --submission ID \
  --return-file ABS --source-root ABS --artifact REL|LOGICAL \
  [--retrospective] [--source-commit HEX] [--return-includes-prime-review]
python -B return_capture.py verify --book BOOK --member 01NN.slug
```

`--book`, `--return-file`, and `--source-root` are absolute. Reserve and capture require a plain book directory outside any Git working tree, so a package cannot be sealed inside the shared checkout. Verify only reads. It may read a sealed copy after that copy has been placed in a repository, and it still does not write. Publication is a later copy into a different disposable repository.

Members are siblings of the band door, `0101` through `0199`, folder `01NN.slug`. `0100.band.returns` is the door, not a member. Any existing directory whose name begins with one of those numbers is taken, including drafts and temporary names. The lowest free number is used. A full band stops. The tool does not create `0200` or another band. Retries do not take an occupied number.

`--name` and `--submission` are windows-safe ids. Origin book and page are single non-empty segments without slashes. `--origin-batch` matches `05.NN`. Submitter, reviewer, and release are non-empty text without control characters. `--expected-output` may be repeated. An empty list means the package is the return file only.

Same submission id and the same reserve fields return the existing reservation and write nothing. The same id with different fields is a conflict and writes nothing. Two overlapping reserves of one id produce one member. Two different ids get two members. The allocation lock is `0100.band.returns/.allocation.lock`, created exclusively for the reserve call and removed by that same call. It is not a member and not a receipt. A lock this call did not create is reported and left for explicit recovery. The tool does not delete member files.

`reservation.json` keys, exactly: `schema`, `kind`, `submission_id`, `origin`, `destination`, `expected_outputs`, `submitter`, `reviewer`, `release`, `supersedes`, `reserved_at`. `origin` is `book`, `page`, `batch`. `destination` is `member`, `name`, `path`. `kind` is `reservation`. `supersedes` is null or an existing member path. The old member is not edited.

`01.md` is written once at reserve. It names the submission, origin, and member, and tells the reader to verify `receipt.json`. It does not store a completion status. Later edits to its prose do not make a package complete.

Capture reads a dedicated return file and an explicit artifact list. It does not search for a Review heading and does not split the return file. Each input is read twice before any capture write. A change between those reads writes nothing. Artifact paths are relative to the source root, forward slashes, no `..`. Logical names are the manifest names. Payload files are flat: `payload/0001.blob` in list order. Source and destination files must be plain files with link count one. Symlinks, junctions, and hard links are refused. Reads stay under the source root, plus the one return file. Writes stay under the reserved member.

`manifest.json` keys, exactly: `schema`, `kind`, `submission_id`, `reservation_sha256`, `return`, `retrospective`, `source_commit`, `captured_at`, `sources`, `omitted`, `required`. `kind` is `manifest`. `return` is `sha256`, `bytes`, `includes_prime_review`. `sources` entries are `logical`, `payload`, `sha256`, `bytes`. `omitted` entries are `logical`, `reason`. The manifest does not contain its own hash. `retrospective` is the caller's flag. `source_commit` is 40 hex when retrospective is true, and null otherwise. `captured_at` is the time of this capture. The tool does not invent a historic timestamp, a missing file, or a test result. `includes_prime_review` is the caller's flag, recorded, not inferred.

`receipt.json` is written last. Keys, exactly: `schema`, `kind`, `submission_id`, `reservation_sha256`, `manifest_sha256`, `captured_at`. `kind` is `receipt`. Its presence is meaningful only when verify recomputes those two hashes and every payload hash.

JSON is canonical UTF-8: sorted keys, separators `(`,`,`,`:`,`)`, `ensure_ascii` false, one trailing LF, finite numbers, duplicate keys refused. Copies are exact bytes, so CRLF stays CRLF.

A required artifact that is missing is reported and does not create capture files. The reservation stays. A second capture of the same bytes, flags, and outputs prints `already-captured` and writes nothing. Changed return bytes, payload bytes, or those flags are a conflict and write nothing. An amended submission is a new submission id on a new member, with `supersedes` pointing at the prior path.

If return, payload, manifest, or receipt already exists and verify is not complete, capture writes nothing and reports the retained paths. An interruption after `return.md` or before `receipt.json` stays partial. A truncated receipt or a corrupt manifest stays visible. Verify in a fresh process exits 0 only when the receipt binds the current reservation and manifest and every payload byte matches. Otherwise it exits 2. Stdout of a complete verify says the capture is complete and that it is not approved, not accepted, and not published.

Exit 0 is a completed reserve, an idempotent reserve, a completed capture, an idempotent capture, or a verified receipt. Exit 2 is a refusal, a conflict, a partial package, a missing input, a full band, or a failed verify.
