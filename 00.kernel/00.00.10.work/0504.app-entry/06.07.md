## What the checker will do
Location: `labs/pack-custody-pass01/`. Standard library and the Git CLI only. No application entry dispatch. The tool verifies declared snapshot bytes. It does not judge pack readiness, meaning, instruction sufficiency, approval, release, dependencies, or whether running a pinned source would be safe.

The format is an explicit `--format`. `tsv` requires the exact header and a caller-supplied snapshot root (the older example's root is `inputs/`). `prime-pack-sources/1` reads `sources[{path,sha256,bytes,snapshot}]`. Snapshot paths in that format resolve under the manifest's directory. Optional `commit` and `repository` are copied into the report as labels. Filesystem mode does not call Git, even when a label is present.

A manifest is pinned before any snapshot is opened: raw bytes, sha256, then a strict parse. An empty file, a header with no rows, a truncated or malformed body, an unknown schema, a duplicate key, a duplicate path, or an ambiguous alias is invalid. Invalid input exits 2 and does not become a clean pass. A bool is not a byte length. SHA-256 must already be 64 lowercase hex characters. Comparison uses the raw snapshot bytes, so CRLF and LF stay different.

Paths must already be canonical relative paths. Absolute paths, drive paths, UNC paths, backslashes, traversal, empty segments, and aliases that differ only by case or Unicode normalization are rejected. A symlink or junction on a snapshot path is a finding. The checker does not follow it outside the declared root. A row that names the manifest file is hashed as bytes and is not loaded as another manifest or as code.

Git mode takes a local repository, an explicit revision, and repository-relative manifest and, for TSV, snapshot-root paths. The revision is resolved once to a full commit. Blobs are read at that commit. The worktree, the index, and the remote are ignored. A missing blob stays missing even if the worktree has a file of that name. The checker does not fetch, check out, change config, or run the pinned sources.

`--json` writes one `pack-custody-report/1` object to stdout. Without it, the same facts are printed as text. Exit 0 means every declared snapshot matched. Exit 1 means the manifest was valid and at least one snapshot was missing, mismatched, linked, or unreadable. Exit 2 means the input was invalid or unsupported, or the tool failed. Expected failures do not print a traceback. `not_checked` always names meaning, instruction sufficiency, approval and release, dependencies, and execution safety. Live-source drift is also not checked. Drift does not rewrite a snapshot and does not, by itself, fail an intact historical blob.
