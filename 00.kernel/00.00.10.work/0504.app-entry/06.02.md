## Contract
The fixture file cannot name its writable container. `allowed_root` is not a fixture field. A fixture that still carries it stops as an unknown key before the payload runs.

One implementation, `app/context.py`, designates the container. The hardcoded pair is `app/scratch` and `00.kernel/00.00.10.work/0504.app-entry/fixtures`. `fixture_containers` in `app/development-workspace.json` must be that pair in that order. The configuration cannot widen it. The directories do not have to exist at validate time.

Inside this workspace, a fixture root must resolve inside exactly one of those two directories. Any other workspace path is refused. A fixture root outside the workspace requires `--container`. The named directory must contain the root, must not be a filesystem or drive root, and must not overlap the workspace. An optional `--container` on an in-workspace root must resolve to the same designated directory.

The choice is made before `fixture.json` is read and before the runner is imported. The entry then stores `designated_container` on the loaded fixture. Exact-key loading refuses a JSON file that tries to supply that key. `check_allowed_root` keeps the two-argument signature the existing runner calls. It requires the entry-set container, and it refuses an output that resolves outside that container.

Paths are resolved, including directory junctions, before the checks. A junction that leaves the fixture root stops as `path escapes the root`. A junction used as `--root` is followed by the entry before the container check, so a junction to `app/` is the `app/` directory and is not a container.
