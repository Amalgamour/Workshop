## Failure

`wf return --push` cannot open a pass branch that does not exist yet.

Exact error, exit 1:

```
wf: git fetch origin pass/90.50.10.0419.05.02: fatal: couldn't find remote ref pass/90.50.10.0419.05.02
```

Where: wf a823ee28, `src/cmd.rs` `ret`, which calls `merge_into_shared` before it records anything. `merge_into_shared` runs `git fetch origin <branch>` and then `git checkout -B <branch> origin/<branch>`. The pack's branch was `pass/90.50.10.0419.05.02`. That ref was not on origin. Fetch failed, so the return was not filed and no `return-refused` entry was written. The claim stayed only in the local page log.

What got the return through, with no force push: create the branch at the pack start, which is already an ancestor of the builder commit, then run the same `wf return --push`.

```
git push origin 4dc2e0f076326657a7f4ac232bf8edd6733464c2:refs/heads/pass/90.50.10.0419.05.02
```

wf then fast-forwarded that branch to fa82cf29 and pushed the log commit b8b1d2da. The return file still says `noticed: none`, because the failure happened at push time, after that file was committed.

Fix: when `return --push` is aimed at a branch origin does not have, create that branch from the pack start (or from the builder commit when the start is its ancestor) and go on. Do not force. If the branch exists and the commit will not merge, keep the current refusal. A fetch failure should also be visible in the log, or the message should say the branch was never created.
