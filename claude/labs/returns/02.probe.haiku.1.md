# Probe 02: reading chains

1. `4.7`: The writer is saying a why is missing. The next reader should not invent a reason. They should ask why it is missing, and recover it only in proportion to the cost of being wrong, with permission. Without permission, leave it missing and report it.

2. `7.4`: The writer is saying something is missing, and the gap concerns a why. The next reader should note the gap first, then look for the why in what is written. If it is not there, leave it missing and report it. Do not invent it. The pack's own examples read this order differently, so this reading is provisional (see last question).

3. `7.8`: A connection is missing. The pack gives this exact example. The next reader should not search for the connection. They should work around the hole, state that the connection is absent, and report it if it is required.

4. `8.7`: A connection is named, and the pointer to it is missing. The next reader should record the pointer as open, not fill it from the shape of the name, and report it. Note that 8 is still a proposed axiom, not yet scrubbed.

5. `1.7`: Authority for something is missing. The next reader should not assume who holds authority. They should ask why it is missing and whether they have written permission to solve it. If no authority can be found, halt and raise it to whoever holds more. Do not choose.

6. `7.1`: The gap is in authority: a grant is absent. The next reader should not treat the work as authorized. They should leave it missing, and report it.

7. `2.5`: Fractal and frame. The next reader should inherit what the parent frame already agrees, write only the difference, and confirm the difference fits the frame's aim, stop point and done condition. A difference that contradicts the parent needs a named override approved above it.

8. `5.2`: Frame, then fractal. The next reader should first set the frame (aim, why, where to stop, what done looks like), then inherit the agreed parent content inside it. Observations outside the frame are reported, not acted on.

9. `1.7.8`: Authority, then missing, then connection. This is the cold set before a write. The next reader should confirm authority first, list what is missing without filling it, and check connections in the same change. They should work around holes and not rewrite the connected items.

10. `3CM`: Compute leads, then the model. The person is not named, so this chain does not assign the person a lead. The next reader should give the work to compute first and the model second. A lead is not authority, so the person's authority is unchanged.

## Last question

Yes, by the pack's own rules order carries meaning. The dot form is an ordered sequence ("authority, then missing, then connection"), and axiom 3 makes order explicit (`3MPC` names the lead first). Order also changes which axiom governs and which one marks a gap.

The pack does not settle the order for a bare `7` marker, though, and its examples conflict: `4.7` is described as "a why" (missing after the subject) while `7.8` is described as "a connection" (missing before the subject). So the writer cannot yet tell from the pack alone which position `7` takes.

How I would decide, using the pack's cold set `1.7.8` as the only fully specified order:
- Put the governing axiom first (authority, then the axiom it governs).
- Put the gap marker `7` next, where it marks what is missing.
- Put the connection last, as the thing the reader must check.
- When two axioms refine each other, put the more general one first, since a later axiom refines and does not replace.

The pack should fix one rule for `7`, and `4.7` versus `7.8` should be reconciled, before chains are relied on.
