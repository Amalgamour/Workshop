## 2. Loops

### Pack, claim, return, check, signoff, close

1. **Pack.** Prima records Matthew’s grant and goal, the done-when, the start commit, branch, worker, checker, tool revision, sources, dependencies and checks. Dry-run the checks through the path workers use on Windows and Linux. The compute can validate the frame and check syntax. The reviewer judges design fit. Matthew’s Stage 1 rule treats all Workshop work as novel for now. `docs/review/DIRECTOR-WORDS-t416u.md:6–11`, `docs/review/DIRECTOR-WORDS-t424.md:9–10`, `docs/plan/GROK-BUILDER-QUEUE.md:42–50`.
2. **Claim.** The worker asks for the named page and next action. The compute checks the pack and assigns or confirms an available counter. If 05.03 has been taken, use the next available counter for new work. Keep already-issued work and evidence on their original counters. The log presently refuses a second claim on a taken counter. `MATTHEW-RESPONSES.md:6`, `src/cmd.rs:435–449`.
3. **Return.** The worker supplies the commit, the actual scope and tests, the design review and remaining gaps. The compute checks the pack pin, scope and allowed transitions. Before publishing, require that the new page log preserves the published history and adds the intended event. If two prepared returns use different counters and the published history has advanced, continue from the published head and revalidate the pending return there. A rejected reconciliation needs a visible reason and a recovery path. The two 0701 returns show why a unique counter alone is insufficient. Until this is enforced, Codex proposes that Prima sequence same-page publishing and compare the new log with the last published log. `src/cmd.rs:484–578,623–631`, `.workshop/logs/90.50.10.0701/log.jsonl:22–24` at `b71ab3e` and `a3a0f83`.
4. **Check.** The independent reviewer runs packed checks and judges each goal against the returned commit. Keep the command record and the reviewer’s judgment distinguishable. When someone files a reviewer’s judgment for them, record the judgment author, actual filer and source of the judgment. An infra failure gets an explicit label so a checker can still report a substantive finding. `src/cmd.rs:724–788`, `.workshop/logs/90.50.10.0702/log.jsonl:18–19`, `MATTHEW-RESPONSES.md:10`.
5. **Signoff.** Prima uses the checker’s evidence and the page goal to accept, carry or discard job cards, with the reason. Strong claims such as Windows readiness need Windows evidence. If the goal changes after the check, request a check of the revised scope. A returned commit, a passed command and a passed signoff are different milestones. `docs/DESIGN.md:56–65`, `.workshop/logs/90.50.10.0703/log.jsonl:8–11`.
6. **Close and recover.** Publish the close as another event and confirm the board and searchable record open the exact return, check and why. If two archived logs diverge, retain both sources and ask Prima to arrange an authorized recovery event with their pins. The lost 0701 event illustrates why recovery needs the old sources. Capture the stage’s actual walkthrough and ask Matthew for go, hold or redo. `docs/AXIOMS.md:25–31`, `docs/review/DIRECTOR-WORDS-t422.md:11–12`, `.workshop/logs/90.50.10.0701/log.jsonl:22–24` at `b71ab3e` and `a3a0f83`.
