# Lessons from lab 0703

- **Set one write durability level before timing.** Pass 05.01 timed buffered Git and log writes against SQLite with `synchronous=FULL`. The different flush work made the ranking hard to interpret. Run all stores at a declared common level, then repeat at a durable level before choosing a production writer. (Commit `05cd58a`, `labs/0703/src/store.rs`; 05.02 report, §3.)
- **Hold the edit and the reference constant.** The first pass compared a Git blob, a log link and a SQLite payload hash as if they answered the same question. Retain one outside digest of the relevant version history. Change the same byte in each store, then see what a self-consistent rewrite can hide. (Commit `05cd58a`; `labs/0703/src/main.rs:71` and `:109`.)
- **Exercise a second version before weighing history.** Insert-only data hid the log’s first-match read and left Git’s commit chain untested as history. Time a representative update, check that the old bytes are still available, and verify that every ordinary read returns the latest version. (Commit `05cd58a`; `labs/0703/src/store.rs:110` and `:132`.)
- **Test damaged record boundaries.** The first pass changed a byte and reported the following record, leaving interrupted and missing writes untested. Test a partial final record and a removed middle record, and use the record checksum to identify a changed payload exactly. Audit a whole suffix with a trusted checkpoint. (`labs/0703/src/store.rs:378`; `labs/0703/src/main.rs:278` and `:295`.)
- **Compare at the granularity the ruling calls for.** Pass 05.01 compared whole pages and proposed changing the authoritative store without weighing the face-file plan. Test face and counter reads and updates against the ruled layout before recommending a change to it. (`docs/design/SEQ-FILE-PLAN.md:246` and `:251`; `docs/spec/DIRECTOR-RULINGS.md:192` at `8e96151d`.)
