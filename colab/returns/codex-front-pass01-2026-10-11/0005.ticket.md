# 0005.ticket — compact forms expose an unaccounted-for field

chain: 2.5.8
severity: card/source mismatch
confidence: medium-high

## Chain

0002.schema/01, Job and Agreement -> 0001.law/01, Correspondence -> 0005.ticket/01 Task/Ticket -> 0005.ticket/02 Task/Ticket -> 0005.ticket/04.
A compact form may change form but cannot silently introduce an additional acceptance condition.

## Break

01 Task specifies the internal range, target, and instruction. 01 Ticket specifies the outward range, path, instruction, and return destination, including invalid/not-ready conditions.

02 Task adds `completion condition` to its field list. 02 Ticket also adds `completion condition`. Neither identifies it as optional or explains its derivation. The matching 04 sections repeat those extra field lists. A cold reader can therefore reject a work item that satisfies the named 01 section solely because it lacks this additional field.

Axiom 5 calls for identifying the done of the work. That supports explicit completion reasoning. It does not, by itself, settle whether these specific work-item records require an additional stored field. This finding concerns the source/representation contract, not a recommendation to stop defining done.

## Repair — difference only

The smallest alignment repair keeps the current named law unchanged:

- 02 Task: `Task: id 05.01-05.49; local target; instruction.`
- 02 Ticket: `Ticket: id 05.50-05.99; outward path; instruction; return.`
- Remove the same extra field from the compact-form sentences on 04 Task/Ticket.

If the director intends completion condition to be a required record field, it must instead be stated in the governing Task/Ticket sections, with its meaning and missing-field result, and then carried consistently. That alternative is a law decision, not a card-only repair. If it is merely optional authoring help, label it explicitly so it cannot become an extra validity test.

No change to task/ticket ranges, slot reuse policy, approval boundaries, or the currently withheld work faces is proposed.
