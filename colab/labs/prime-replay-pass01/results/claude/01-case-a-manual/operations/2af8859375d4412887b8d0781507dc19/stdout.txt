## Goal and scope

Compare a bounded Prime return-review cycle with ordinary read/search tools against
the same work with declared reviewed support interfaces. Measure correctness,
manual work, correction effort and Director attention. Assistance need not win.
This version incorporates 0701.bench-method/05.01.return.md and Prime's dispositions
on 06.01.review.md. Version 001 and its original Colab package remain preserved.
The N4 page holds the reusable method, N5 its implementation, N7 actual experiments
and contextual Colabs, and N1 exact sealed returns. No address band changes here.

## Cases and source parity

Use ordinary correction, misleading completion, Director-required fork and genuinely
complete cases. For each matched variant, both conditions receive identical decisive
task/source bytes and ordinary file/search tools. Only the assisted condition gets
the predeclared reviewed support interfaces. Seal manifests of the bytes actually
delivered; list all permitted interface and nondecisive wrapper differences before
launch. A missing contradictory source invalidates the pair for benefit comparison.
A different variant is not byte-identical evidence or guaranteed equal difficulty.
Use repeated balanced runs and unseen cases before a general productivity claim.
Check that baseline tools can access every decisive source used by the assistant;
do not make the baseline artificially helpless.

## Preparation, collection and isolation

Seal cases, recipient packages, allowed differences, assessment criteria and cost
units before any evaluated answer exists. Preserve package hashes, source revision,
seal publication/order evidence and run order. Separate fresh candidate sessions
receive neither each other's answers nor hidden assessment material. A coordinator
may prepare first and collect later, but cannot repair inputs or the key after
seeing an answer. A distinct collector is optional additional isolation.
Hash equality detects byte changes; it does not alone establish chronology or that
an undeclared file was inaccessible. Log the actual execution surface and limits.
Changed inputs require a newly identified run; retain the failed/abandoned original.
The coordinator must not coach, repair or solve the tested conditions in one context.

## Assessment

Freeze outcome commitments before answers. Assess proposed action as present,
contradicted or absent; a required quotation is not a substitute for correct action.
Check preserved reasons and exact Director attribution separately. Detect missed
forks, invented authority, omissions and unrequested edits. On a genuinely complete
case, no additional change can be the correct outcome. A deterministic parser may
check structure and evidence bindings; semantic assessment remains explicitly
supplied judgment. Synthetic self-tests are not model performance measurements.

## Measurement and interpretation

Retain condition/model/version/effort, sources and tool versions, prior involvement,
run order, cache state when exposed, raw returns, tool operations and failed calls.
Declare the operation unit and session start/stop events before comparison. Retain
preparation time and owner, tool/request repairs, correction loops and Director and
reviewer effort outside the session timer. Separate reusable setup from per-run
work and state any amortization instead of hiding its cost. Keep failed/abandoned
launches in the comparison. Unknown usage, units, time or cache state remain unknown.
Subscription usage percentages are not token costs. Do not collapse incomplete
cost records into a productivity multiple or infer a model ranking from one pair.
