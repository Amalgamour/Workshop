## 2. Halt and resume

**What:** Prime or the person can stop a page, and start it again. Both need a note with a reason and a (ref). Both are log entries. Halt is refused while a pass is open (pack, open, return or review).

On a halted page, status shows who stopped it, when, and why. Next says who can resume, and never says "next: draft". Draft, pack and claim are refused, and the message says how to resume. Observe does not report a stall on a halted page.

**Why:** On pages 90.10 and 90.20, status still said "next: draft" after a halt that was only a note. People thought they should start new work. A real halt must say so, and must stop new work, until someone with authority resumes it. [entry 4]

The halt only stops a tool that knows the command. The old pin (8eb1fdb) ignores halt. The pin was rebuilt from a00bc53 at about 3:10 PM EST, so halt is now live.

## 3. A draft waits; overlap only on purpose

**What:** `wf draft` is refused while any earlier pass is not closed (draft, pack, open, return or review). The message names that pass and its next step. A pass still at draft can be redrafted with `--pass`.

Prime may draft a second pass while another is already packed and open, only by naming that pass with `--overlap-ok NN` and a why with a (ref). Without the flag, the refusal stands. A pass that still sits at draft cannot be overlapped. The pack still refuses two open passes that would touch the same files, unless the same flag is used.

**Why:** On 90.20, a draft was accepted while a pass was still open. The pack later refused it as a stale pin. That wasted a step and hid the real problem. The default must wait.

Matthew also ruled that several models can sit at one page (t262u: "sometimes multiple models can sit at this"). So the wait can be lifted on purpose, with a named pass and a why, never by accident.

Pass 05.01 first ended parallel drafts for everyone. That went against the ruling. Pass 05.02 put `--overlap-ok` back, and restored the pack-overlap tests that 05.01 had dropped. Pass 05.03 made the docs cite t262u, not t285u, as the authority.

## 6. Past views keep the template they were packed with

**What:** Packed job boxes (AGENTS.md, PROMPT.md, and the return template) reprint from the template version stored in the pack entry.

- A missing field, or the string "1", means v1: the 8eb1fdb text, kept in the binary under `templates/v1/`.
- The string "2" means v2: the current `templates/` text.
- Any other value is refused. The message names the page and the pack entry.

New packs record version 2. Escape and other output changes do nothing to clean text, so past real pages still verify, and `verify --fix` changes no file on them.

**Why:** Pass 05.02 edited the templates. The new binary then reprinted every past job box with the new wording. `wf verify` failed on pages 90.10, 90.20 and 90.30. `--fix` would have changed what past builders were handed. That breaks axiom 6: the past stays. This was the stop-if case. Tester caught it. [entry 18]

Pass 05.03 added the version field so a template change applies only to new packs. Pass 05.04 made the field strict: only a missing field or the string "1" is v1, and only the string "2" is v2. A number, a blank, or any other value is refused. [Tester entry 26 found a non-string was read as v1; entry 35 confirmed the strict rule.]

## 7. Input is refused by character kind, not a short list

**What:** One shared check covers command flags and pack fields. It refuses every character whose Unicode kind is Cc or Cf (control or format, including the escape character, CR, bidi marks, zero-width joiners, and tag characters), Zl or Zp (line and paragraph separators), or Co or Cn (private-use or unassigned).

It also refuses the Hangul fillers U+3164, U+115F and U+1160, and a field that is only combining marks. CR is refused everywhere. A newline is kept only in face text (`--file` or `--text`) and in pack field values. Draft field keys are checked too.

The check is a small table in the source (Unicode 15.1.0). There is no new crate. Tester agreed with Python on all 1,112,064 code points.

**Why:** A newline in a halt note could print a fake "next:" line on status (Tester entry 9). Pass 05.02 blocked only a short list of control characters, and only in notes. Tester entry 18 showed that names, titles, and other invisible characters still got through.

Pass 05.03 widened the list and applied it to typed flags. Tester entry 26 showed two remaining holes. The list still missed some invisible kinds. And it never ran on what a builder writes (return job lines, changed file names, draft keys). A short list will always miss the next new character. The category table covers the kind, including characters that were not in our list yet.

## 8. Builder text is escaped on output

**What:** Text that came from a builder (return file job lines, notes, elevation items made from them, and changed file names from git) is shown escaped, for example `\u{1b}`, in status, observe and the 05 views when it contains a refused character. A hostile return can still be logged as evidence. The escape does nothing when the text is clean, so past views stay the same.

**Why:** The builder is the lowest-trust role. Typed flags can be refused. A return file and a git path cannot always be refused, because they are already written, and they are evidence. They must never print raw on a screen an observer uses to check the work. Matthew ruled this direction in t309u to t312u: guard the compute, so an observer can check. [entries 26 and 29]

## 9. What is still open (`7`)

These are from Tester's check of 05.04 (entry 35). They are not fails. They wait for a later pass or for Matthew.

1. **Joiner characters are format characters (Cf), so they are refused.** Emoji that use a zero-width joiner, and some Hindi or Persian words that use a zero-width non-joiner, cannot be typed as a name or a note. Accented names, CJK, Arabic, Hindi letters, Thai, flags, skin tones and the emoji variation mark are accepted. This is a usability tension. It needs Matthew's ruling. `7`
2. **Two blank-looking characters are still accepted:** U+FFA0 (halfwidth Hangul filler) and U+2800 (Braille blank). They can spoof a name. `7`
3. **When `wf return` is refused, the error printed to the builder's own terminal still shows the raw file name.** That text is stored in the log's why field. No view shows it raw. [cmd.rs:447-455; escaped on the 05 view at render.rs:145] `7`
4. **The real-pages test skips with a printed note if the pages folder is missing.** [tests/wf.rs:1388-1392] On another machine, `cargo test` still counts that as a pass, so the skip is easy to miss. `7`
