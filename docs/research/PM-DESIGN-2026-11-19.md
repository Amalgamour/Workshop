## 3. Work breakdown [WBS]
- What it is: the whole job split into a tree of smaller deliverables ([PMI blog](https://www.pmi.org/blog/work-breakdown-structure)).
- It shows what gets made, not who or when (same source).
- The lowest piece is a work package: one owner, can be estimated and checked (same source).
- The 100% rule: the children add up to all of the parent, no more, no less ([PMI practice standard paper](https://www.pmi.org/learning/library/practice-standard-work-breakdown-structures-8063)).
- So nothing is left out, and nothing sneaks in.
- Branches should not overlap ([PMI blog](https://www.pmi.org/blog/work-breakdown-structure)).
- A WBS dictionary gives each piece its scope, owner and acceptance test (same source).
- Maps to us (proposal): stage is the top, then band, then page, then pass. Our address already is a tree (Axioms.md:23, "the address is the line written down").
- Page = work package: one lead (Axioms.md:17), a done-when (ROADMAP-2026-11-18.md:127).
- Face 01 + face 04 act like the WBS dictionary entry for a page.
- The 100% rule fits axiom 2 (write only the difference) and axiom 5 (where to stop) (Axioms.md:15, :21).
- Gap: nothing checks that a stage's pages add up to the stage goal (7).

## 4. Dependency graphs, critical path [CPM] and PERT
- A dependency graph: boxes for tasks, arrows for "this must finish before that" ([VT Principles of PM, ch. 8](https://pressbooks.lib.vt.edu/principlesofprojectmanagement/part/chapter-8-building-the-schedule-activities-dependencies-and-the-critical-path/)).
- Forward pass: earliest start = the latest finish of all tasks before it ([PMI CPM basics](https://www.pmi.org/learning/library/critical-path-method-calculations-scheduling-8040)).
- Backward pass: latest finish = the earliest start of all tasks after it (same source).
- Float [slack]: how long a task can slip without delaying the end (same source).
- Critical path: the chain with zero float; any slip there delays the whole job ([VT ch. 8](https://pressbooks.lib.vt.edu/principlesofprojectmanagement/part/chapter-8-building-the-schedule-activities-dependencies-and-the-critical-path/)).
- PERT: three guesses per task (best, likely, worst); expected = (best + 4 x likely + worst) / 6 ([Penn State SE505](https://sites.psu.edu/se505/lesson-8-project-planning-and-scheduling/)).
- CPM suits known work; PERT suits uncertain work (same source).
- Maps to us (proposal): a page is a box; an arrow is a written link saying "this page needs that page's return".
- Axiom 8 says a connection is lawful only when written (Axioms.md:27). So arrows must be written, never guessed from matching names.
- Today only one link exists: a pass's `predecessor` (PACK-TEMPLATE.md:94). It links passes, not pages (7).
- Durations: our pass is a fixed 30-50 minute slot (LOCAL-BUILDER-FLOW-t400u.md:6). So count passes, not hours.
- The bench already counts passes per goal (ROADMAP-2026-11-18.md:131). That could feed a PERT-style best/likely/worst in passes.
- Critical path for us: the longest chain of pages that need each other. Those pages go first; the rest can wait or run alongside.

## 5. Construction and body-shop scheduling
### Last Planner System [LPS]
- Plans at levels: master, phase, a 6-week look-ahead, then a weekly work plan ([LCI workbook](https://leanconstruction.org/wp-content/uploads/2022/08/Last-Planner-System-Workbook.pdf)).
- Make-ready: remove each constraint so a task goes from "should" to "can" before anyone is given it (same source).
- Constraints include missing information, materials, people, space, and unfinished earlier tasks ([AUB paper](https://scholarworks.aub.edu.lb/server/api/core/bitstreams/795f7a46-6c55-449d-88ae-3f917ffa4edd/content)).
- Only "quality assignments" are promised; this shields crews from upstream mess ([LCI workbook](https://leanconstruction.org/wp-content/uploads/2022/08/Last-Planner-System-Workbook.pdf)).
- Percent Plan Complete [PPC]: promised tasks done / promised tasks; good teams reach 75-90% ([LCI PPC sheet](https://leanconstruction.org/wp-content/uploads/2022/08/11_LPS_Percent_Plan_Complete-PPC.pdf)).
- Each week, ask why a promise failed, and fix the cause (LCI workbook).
- Maps to us: make-ready = `wf pack` checks before a pass is released; a pack that fails stays draft (workflow-loop.md:160).
- Our pack lists "read first" files and checks each link opens (PACK-TEMPLATE.md:108). That is a make-ready check.
- PPC = our bench "first-try rate" (ROADMAP-2026-11-18.md:131; bar 60%, :133).
- "Why it failed" = face 06 notes feeding the next pack (LOCAL-BUILDER-FLOW-t400u.md:32).
### Takt planning
- Split the building into zones of equal work; each trade [wagon] moves one zone per fixed beat [takt] ([HSM CON-410](https://hsmuniversity.org/us/course/con-410-lean-construction-and-productivity/lesson-7-takt-time-planning-and-line-of-balance)).
- Duration = (zones + wagons - 1) x takt (same source).
- One late wagon can stop the whole train; small buffers absorb slips ([HSM CON-335](https://hsmuniversity.org/us/course/con-335-trade-coordination-and-short-interval-planning/lesson-4-flow-on-repetitive-floors-zones-trade-trains-and-stacking)).
- Work packages in one wagon should not get in each other's way ([Lean Construction Blog](https://leanconstructionblog.com/Introduction-To-Takt-Planning.html)).
- Maps to us: the 30-50 minute pass is already a beat. Sizing each pack to fit one pass is like balancing a wagon.
- Our 4-hour check (LOCAL-BUILDER-FLOW-t400u.md:24-26) is a coarser beat for review.
### Body-shop production boards
- Stages: check-in, teardown/blueprint, parts, body, paint, reassembly, calibration, QC, delivery ([Bodyshop Software Guide, workflow](https://bodyshopsoftwareguide.com/articles/collision-shop-workflow/)).
- Each stage needs an entry and an exit condition, and a named person who accepts the handoff ([Bodyshop Software Guide, boards](https://bodyshopsoftwareguide.com/articles/collision-production-board-guide/)).
- A blocker is a reason plus an owner, not a new column (same source).
- Don't release a car into a stage it can't finish for lack of parts ([Claimory](https://claimory.io/blog/how-to-run-a-collision-shop-production-schedule)).
- Find the bottleneck (often paint); never starve it, never overload it (same source).
- Short daily check of what is stuck; tools flag stall-outs ([OpVantis](https://www.opvantis.com/production-boards)).
- Maps to us: our columns already carry body-shop side labels: estimate, ready for a bay, in the bay, waiting QC, QC done, delivered (WF-BOARD.md:29-36).
- Entry/exit conditions = tails, moved only by wf (board-dev:README.md:27-32).
- Blockers = ATTENTION lines: questions, halts, returns waiting (WF-BOARD.md:41-52).
- Stall-out = `STALE` after 24 hours with no log entry (WF-BOARD.md:56).
- Our bottleneck is review: Matthew on every pass would be the bottleneck (docs/design/ONE-PAGE-WORK.md:287).
- QC by someone other than the builder (axiom 9; Axioms.md:29; workflow-loop.md:164).

## 6. Kanban with WIP limits vs stage gates
- Kanban: work items on a board; a WIP limit caps how many sit in a column or the whole system ([Kanban University guide](https://kanban.university/kanban-guide/)).
- When a column is under its limit, that free space is the signal to pull the next item (same source, [glossary](https://kanban.university/glossary/)).
- Less work in progress means each item finishes sooner [Little's Law] ([Kanban Guide for Scrum Teams](https://scrumorg-website-prod.s3.amazonaws.com/drupal/2019-09/2019-09-Kanban-Guide-for-Scrum-Teams-English.pdf)).
- Stage gate: work runs in stages; at each gate a person decides go, kill, hold or recycle ([Cooper, Latest View on Stage-Gate](http://www.bobcooper.ca/images/files/articles/2/2-2-The-Latest-View-on-Stage-Gate.pdf)).
- Hybrid: gates for the big decisions, short agile cycles inside each stage ([Cooper 2016, Agile-Stage-Gate Hybrids](https://doi.org/10.1080/08956308.2016.1117317)).
- Maps to us, kanban: the page board is already a kanban of 05.NN cards (workflow-loop.003.md:160; WF-BOARD.md:29-36).
- Maps to us, WIP: one open pass per page by default (board-dev:README.md:97). That is a WIP limit of 1 per page.
- No limit exists across the book or per builder (7). Matthew's PC and the review queue are the real limits.
- Maps to us, gates: the end of each roadmap stage (hostile pass, halt, report to Matthew; ROADMAP-2026-11-18.md:130).
- Signoff and close are small gates per pass (board-dev:README.md:32).
- Axiom 1 says authority is granted by a person (Axioms.md:13). A gate is where Matthew grants the next stage.

## 7. When can two tasks run at the same time?
- Computer science test [Bernstein's conditions]: two tasks are independent when neither writes what the other reads, and they don't write the same thing ([Temple CIS 307](https://cis.temple.edu/~giorgio/old/cis307s97/readings/interleave.html)).
- Data dependency: B needs A's output. Then B waits (CPM arrow, section 4).
- Shared resource: both need the same file, branch, tester or machine. Then they queue (body-shop bottleneck, section 5).
- Interface contract: if two teams agree the shape of what passes between them, each can work alone, and a test catches a broken promise ([Fowler, Consumer-Driven Contracts](https://www.martinfowler.com/articles/consumerDrivenContracts.html); [Fowler, Contract Test](https://www.martinfowler.com/bliki/ContractTest.html)).
- A contract starts a conversation; it does not replace one ([Pact FAQ](https://docs.pact.io/faq)).
- Maps to us, files: wf already refuses two passes on the same files (board-dev:README.md:95). That is the "same write" half of the test.
- Maps to us, reads: no check today that pass A reads a file pass B writes (7).
- Maps to us, data: written face 08 links between pages (workflow-loop.md:89) could carry "needs".
- Maps to us, contract: face 01 done-when plus pack checks act as the promise a later page can rely on (PACK-TEMPLATE.md:99, :107).
- The workflow spec already warns that concurrent writers make origin unclear; isolated worktrees are a candidate (workflow-loop.003.md:81).
- Matthew's test in plain words: "independant branches that don't rely on each other" (DIRECTOR-WORDS-t420.md:12).

## 8. What a minimal PM template holds
- WBS dictionary: scope, owner, milestones, acceptance (PMI blog, above).
- Definition of done: the quality bar work must meet to count ([Scrum Guide 2020](https://scrumguides.org/docs/scrumguide/v2020/2020-Scrum-Guide-US.pdf)).
- Body-shop card: stage, next action, owner, parts readiness, promise date (Bodyshop Software Guide, boards).
- Last Planner card: constraints cleared, who promised, done or not, and why not (LCI workbook).
- Common core across all of them: goal, pieces, order, owner, done-when, risk, blockers.

## 9. Where sources disagree (no winner picked)
- CPM vs Last Planner. One side: CPM finds the critical path and float (PMI CPM basics). The LCI workbook uses both.
